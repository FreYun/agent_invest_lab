# 虚拟人基金投资三层框架设计

**起草日期**:2026-04-29
**适用对象**:参与公募基金直投的 bot
**与现有方案的关系**:本框架是一份**方法论上位文档**,在现有《基金投资完整链路》(`workspace/skills/portfolio/_shared_docs/fund-investment/基金投资完整链路.md`)之前增加一道"能力圈宣告"前置阶段。框架只规定形态边界与接口契约,不规定操作细节;细节由各 bot 在 `基金投资策略摘要.md` 中按人设自定义。

---

## 一、设计原则

1. **投资合法性优先**:bot 必须先回答"凭什么能在公募基金上赚钱",再做配置和择时。
2. **三层垂直依赖**:上层(能力圈)决定中层(资产配置)和下层(风控)的形态。能力圈一旦确定,中下层的策略形态被框定。
3. **框架只规定形态边界与接口契约**:具体信号、阈值、选基筛选逻辑、择时规则等细节由 bot 自己定。
4. **bot 自评驱动**:能力圈不由研究部派定,由 bot 基于自己的 SOUL/MEMORY/历史投资记录自评。
5. **形态切换保持原子性**:复合能力圈 bot 在不同范式间切换时,整组合调整,不在同一组合里混架构。


## 三、能力圈分类与自评机制

### 3.1 四种能力圈

每种能力圈对应一种独立的赚钱机制。bot 自评时必须能回答:这种钱我懂为什么能赚到吗?有什么证据证明我的判断有效?

#### A · 宏观周期把握
- **赚钱机制**:在经济周期不同阶段切换股、债、金、现金的权重,赚大类资产 beta 切换的钱。
- **必备知识储备**:利率周期、估值分位、通胀/PMI/社融、信用利差、汇率、央行货币政策。
- **自评证据要求**:bot 的 SOUL/MEMORY/历史日记里,有持续跟踪宏观指标、基于宏观信号做过判断并被验证的记录。

#### B1 · 行业轮动
- **赚钱机制**:在多个行业之间根据相对强弱/景气度比较做权重切换,赚行业切换 beta 的钱。
- **必备知识储备**:多个行业的产业链 + 行业之间的相对估值、相对动量、风格切换、政策风向。
- **自评证据要求**:bot 同时跟踪多个行业、有做过行业切换的判断并被验证。

#### B2 · 单行业深耕
- **赚钱机制**:只研究一个行业,在该行业的 cycle 内部做择时,赚单一行业景气周期的钱。
- **必备知识储备**:单一行业的产业链全景、龙头公司、产能/订单节奏、行业历史估值分位、行业自身的拥挤度/景气度信号。
- **自评证据要求**:bot 在该行业的研究深度、跟踪持续性、对行业 cycle 历次拐点的判断记录。

#### C · 个基 alpha
- **赚钱机制**:选出能持续跑赢同类基准的基金(指增、量化、长期 alpha 稳定的明星经理),赚产品超额收益的钱。
- **必备知识储备**:基金经理任职年限与历史业绩、超额收益归因、风格稳定性、夏普/卡玛/回撤、规模与换手率、跟踪误差。
- **自评证据要求**:bot 有筛选基金的方法论、跟踪过基金经理变更/风格漂移、选出过被验证的基金。

> **B1 与 B2 互斥**:一个 bot 在能力圈 B 上要么是轮动型,要么是单行业深耕型。bot 仍可以同时具备 A 和 B 中的某种子型,以及 C(可多选 A/B/C 三大类)。

### 3.2 自评的硬规则

1. bot 每个季度做一次能力圈自评,写入 `能力圈宣告.md`。
2. 每项标记为 `true` 的能力,必须能在自评叙述中列出至少一条具体证据(研究记录、历史预测验证、跟踪习惯)。
3. 三种能力圈的自评结果是**独立的**——可以同时具备多种,也可以一种都没有。
4. **一种都没有的 bot,不被允许进入基金投资 cron 链路**(由 Phase B-1 闸门拦截)。

### 3.3 演进的硬规则

- 一旦从 `false` 切换为 `true`,需写明触发的"成立证据"。
- 一旦从 `true` 切换为 `false`,需写明触发的"证伪证据"。
- 不允许在非季度重评窗口里**新增**能力圈(防止牛市自我膨胀)。
- 允许在任何时候**收窄**能力圈(防止熊市硬撑)。

## 四、四种范式的形态特征

每种能力圈对应一种"投资范式"。范式只规定**仓位结构形态**和**风控决策依据来源**,不规定具体信号、阈值、操作细节。

| 范式 | 持仓主轴 | 仓位结构形态 | 风控决策依据来源 |
|---|---|---|---|
| **A 大类资产轮动** | 大类资产(股/债/金/现金) | 每类资产 1-2 只代表性产品,总持仓少而精,大类比例真实生效 | 宏观信号 → 整组合大类比例重定;**不以单基金浮盈浮亏为决策依据** |
| **B1 多行业轮动** | 行业 | 多个行业卫星并存,按相对强弱动态调权,单行业敞口受限 | 行业相对强弱比较 → 行业间权重切换 |
| **B2 单行业深耕** | 单一行业 | 主战行业集中持仓(高敞口) + 缓冲仓 + 现金 | 主战行业自身周期 → 行业内加减仓;主战行业敞口有上下限纪律 |
| **C 个基 alpha** | 单基金 | 核心 + 卫星挑产品,大类比例不极端 | 单基金累计盈亏 + 近期动能 + market regime → 个基止盈止损/SWITCH |

### 关键差异(框架要保证的形态边界)

- **范式 A 的风控不下沉到单基金**——这是范式定义,如果 bot 想做单基金止盈止损,它就不是 A 范式。
- **范式 B2 的"集中"是范式特征**——框架不要求 B2 bot 做行业分散。
- **范式 C 完全可以套用现有 Phase C 单基金矩阵**——天然契合现有择时框架。

具体的"上限是多少"、"什么信号触发调仓"、"选什么样的基金"等细节,**全部由 bot 自己在 `基金投资策略摘要.md` 里按人设和能力深度自定义**,框架不预设。

## 五、Phase B-1 「能力圈宣告」前置阶段

### 5.1 在 cron 中的位置

```
Phase A    数据刷新
Phase A.5  数据新鲜度闸门
─────────────────────────  ↓ 新增 ↓
Phase B-1  能力圈宣告 + 当日范式选择     ← 新增,前置闸门
─────────────────────────  ↑ 新增 ↑
Phase B0   市场环境判断
Phase B    选基(按当日范式分支)
Phase C    巡检调仓(按当日范式分支)
Phase D    收益快照
Phase E    归档
```

### 5.2 Phase B-1 做的事

1. **读 bot 的能力圈宣告文件** → 获取 `capability_levels`。
2. **闸门检查**:四个字段全为 `false/null` → 跳过整轮 cron,记录"未具备能力圈,本日不参与"。
3. **当日范式选择**:
   - 单能力圈 bot:范式自动确定,无需选择。
   - 复合能力圈 bot:读 `基金投资策略摘要.md` 中的"范式切换规则" + 当前持仓的范式标记 + 上次切换日期 → 决定本轮是否切换。具体切换信号由 bot 自定。
4. **写入 `fund_paradigm_runs` 表**:`bot_id, run_date, paradigm_active, capability_used, switched_from, reason`。

### 5.3 输出契约(给后续阶段)

```yaml
paradigm_active: "A" | "B1" | "B2" | "C"
capability_used:
  field: "macro" | "industry_rotation" | "industry_focus" | "fund_alpha"
  value: true | "黄金" | "科技" | ...
```

后续阶段(B0/B/C)的 skill 接收 `paradigm_active`,内部按范式做差异化执行。

### 5.4 复合能力圈的范式切换规则

- 切换由 bot 自己在 `基金投资策略摘要.md` 里写明触发条件(框架不预设)。
- 默认情况下保持当前范式不切换。
- **切换间隔 ≥ 30 天**(避免来回折腾,费率会吃掉超额)。
- 切换必须 commit 全组合调整(原范式持仓清退或转换到新范式架构),不能半混合。

## 六、能力圈宣告的存储与演进

### 6.1 文件位置与结构

每个 bot 在 `workspace-botN/memory/portfolio/fund/` 下新增 `能力圈宣告.md`,结构:

- **顶部 yaml frontmatter**:`capability_levels` 结构化字段(机器读)。
- **正文 markdown**:每项能力的证据、自评叙述、范式切换规则(人读 + bot 自己读)。

示例:

```markdown
---
capability_levels:
  macro: false
  industry_rotation: false
  industry_focus: "科技"
  fund_alpha: true
last_assessment_date: 2026-04-29
next_assessment_due: 2026-07-29
default_paradigm: "B2"
secondary_paradigm: "C"
switch_rules:
  - trigger: "<bot 自己写的切换条件>"
    from: "B2"
    to: "C"
---

## 能力圈自评(2026-04-29)

### B2 单行业深耕 · 科技
**证据**:
- <bot 自己列出的证据 1>
- <bot 自己列出的证据 2>

### C 个基 alpha
**证据**:
- ...
```

> `industry_rotation = true` 时 `industry_focus` 必须为 `null`;反之亦然(B1 与 B2 互斥)。

### 6.2 季度重评机制

新增 `update-capability-circle` 脚本(类似现有 `update-investment-strategy-summaries.py`),每季度第一个工作日触发:

1. 读 bot 这一季度的 `fund_bot_reviews`、`fund_bot_rebalance_actions`、日记、研究文件。
2. 给 bot 一段 prompt:"基于本季度的投资结果,审视你的能力圈宣告——是否有新增能力?是否有被证伪的能力?"
3. bot 输出更新后的宣告,写回文件 + 数据库。

非季度窗口里 bot 自己发现重大变化(比如某个行业研究被证伪),可以**主动收窄**能力圈,但不能新增。

## 七、与现有链路的接入

不重写现有 skill,只约定"范式参数"在链路里如何传递。

### 7.1 接口约定

```
Phase B-1 输出 paradigm_active   ──┐
                                   ├─→ Phase B0   (skill 内部根据范式调整输出重点)
                                   ├─→ Phase B    (skill 内部根据范式调整选基逻辑)
                                   ├─→ Phase C    (skill 内部根据范式调整巡检逻辑)
                                   └─→ Phase D/E  (snapshot/归档加 paradigm 标签)
```

### 7.2 各 Phase 的差异化由谁决定

| Phase | 范式差异由谁决定 |
|---|---|
| B0 | 由 `market-context` skill 根据 paradigm 自定调整,**框架不规定具体差异** |
| B | 由 `fund-match` skill 根据 paradigm + bot 的策略摘要决定选基逻辑,**框架不规定具体差异** |
| C | 由 `fund-review` skill 根据 paradigm + bot 的策略摘要决定巡检逻辑,**框架不规定具体差异** |

> 框架只保证"paradigm 参数被传下去 + 各 skill 知道当日是哪种范式";具体如何因范式调整由 skill 自己实现 + bot 自己写策略。

### 7.3 库表层面

新增两张表:
- `fund_capability_circle` — 能力圈宣告快照(每次重评写一行)。
- `fund_paradigm_runs` — 每日 Phase B-1 输出(本日范式 + 切换原因)。

现有表 `fund_bot_reviews` / `fund_bot_actions` / `fund_allocation_runs` 添加 `paradigm` 字段,做溯源。
