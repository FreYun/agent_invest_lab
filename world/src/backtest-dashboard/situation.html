处境地图 · 16 个格子

纵轴是市场压力（平静 / 偏紧 / 紧张 / 极端），横轴是近 20 日回撤（无 / 浅 / 中 / 深）。 格子里第一行大字是日级先例数（1,619 个交易日摊进来的），底下橙色一行是案例数（121 例）。 这两个数永远不相加——案例不是交易日的随机抽样，它们是被挑出来写成案例的日子，本身就带选择偏差。并排放是为了让你看见两者差多少。 点任意格子看它里面到底是些什么日子。

底率 · 每个处境格的后续净值分布

只出分布，不出均值。 均值会被一两个极端值拖着走，而在 n=7 的格子里，一个极端值就是全部。 下面每格给 p10 / p25 / 中位 / p75 / p90 和胜率，画成一条带；带子有多宽，不确定性就有多大，这件事必须让你一眼看见。
分母给三个数：n行 是命中的交易日数，n独立 是互不重叠的窗口数（20 日窗口在相邻两天之间重合 19/20，1,246 个日子远不是 1,246 个独立观测），nbot 是涉及几个 bot——全部来自同一个 bot 的「底率」只是那个 bot 的历史。够不够格出数字，只认 n独立。

🔒
as-of 是闸门，不是筛选器。 一条 D 日的处境，它的 20 日后果要到 D+20 才知道。查询里强制写着 outcome_available_at <= as-of，所以你把 as-of 调到 2025 年，能看到的样本就会变少——这正是它在工作的样子。去掉这一行就是拿 8 月的结果去解释 5 月的决策。想看它到底有没有在工作，去「PIT 闸门实证」页。

卡片与谓词 · 哪张卡凭什么说它管这件事

一张卡要参与判定，先得把「什么情况下算适用」写成可复算的谓词。写不出来的卡不是不好，是还不能被机器判、也不能被证伪——它们不进判定表、不产生边、不出现在处境格里。这个区分必须显示出来，否则会让人以为整个库都已经机械化了。
每张卡都声明了命中意味着什么（违反 卡说别这么干 / 处境 只是描述处境 / 缺陷 指向一个缺陷 / 流程 流程问题）。 这是声明的，不是推断的：如果默认「命中 = 违反」，有一张卡的 1,246 次日级命中会当场变成 1,246 次凭空捏造的违规。

关系边 · 每一条都要回答「这条边凭什么」

basis 这一列是这张表的主键级信息，前端必须显示它。两种凭据绝不能混着读： mechanical_predicate 是机械判定，可复算可证伪，改一行代码结论就会变； card_provenance 是卡片自报的出处，机器一个字都没验过，只是把卡里写的原话搬了过来。 把它们放进同一列而不标注来源，就是让没验过的东西冒充验过的东西。

结果覆盖 · 有多少主体根本没有后续结果

这个数必须摆在前面，否则底率会看起来比实际扎实。窗口不够就留白，不许拿最后一天顶数——写 0 或者用现有的最后一天替代，等于把「还没发生」记成「发生了且没动」。 案例写在 run 的活边缘上（写案例的那天往往就是这个 run 目前的最后几天），所以案例线的留白比例天然远高于日级线。这是结构性的，不是数据缺口，补不了。
