# Bot101 每日投资决策流程与 Token 成本说明

## 一、文档摘要

Bot101 是面向多指数权益基金配置场景的智能投资决策 Bot。它每天按照固定流程完成市场分析、主线识别、持仓检查、基金筛选、仓位控制和交易决策，并保存完整的决策依据与风险观察结果。

Bot101 的核心特点不是“每天都交易”，而是“每天都检查”。当市场趋势、投资主线和账户风险没有出现足够明确的变化时，系统会选择维持原有组合，避免因频繁交易增加成本和判断误差。

根据 2026 年 6 月 11 日至 2026 年 8 月 3 日共 37 个实际交易日的运行记录：

- 实际使用模型为 `qwen3.6-plus`。
- 全样本平均每个交易日使用约 **42.23 万 Token**。
- 系统进入稳定运行阶段后，平均每个交易日使用约 **24.13 万 Token**。
- 按本文采用的参考单价估算，稳定阶段平均成本约为 **0.52 元/交易日**。
- 按每月 22 个交易日计算，单个 Bot 每月约使用 **530.8 万 Token**，模型费用约为 **11.46 元**。

> 本文中的 Token 数量来自 Bot101 的实际运行记录；费用为参考估算，不代表供应商最终账单。

## 二、Bot101 每日投资决策流程

### 1. 每日流程概览

Bot101 每个交易日按照以下流程完成投资判断：

| 环节 | 主要工作 | 主要输出 |
|---|---|---|
| 1. 读取账户与市场数据 | 获取账户资产、现金、持仓、收益、回撤、基金净值和主要指数状态 | 当日决策所需的数据底座 |
| 2. 判断市场环境 | 综合宏观、估值、趋势、情绪、波动率和资金等信息 | 风险状态、市场趋势、估值位置 |
| 3. 识别市场主线 | 判断当前是否存在持续性较强的行业或主题机会 | 核心主线、辅助主线、主线置信度 |
| 4. 复核现有持仓 | 检查原有持仓的趋势、盈亏、持有时间和风险状态 | 继续持有、减仓、退出或替换建议 |
| 5. 筛选投资基金 | 在确认需要新增或替换的方向中选择基金载体 | 1—3 只候选基金及筛选理由 |
| 6. 确定组合仓位 | 将市场环境和主线强度转换为实际仓位 | 总仓位、核心仓、辅助仓和现金比例 |
| 7. 执行风控检查 | 检查回撤、趋势破坏、估值过热和交易频率 | 是否允许加仓、减仓或暂停交易 |
| 8. 形成交易决策 | 生成买入、卖出、调仓或维持不动指令 | 当日最终投资决策 |
| 9. 保存决策记录 | 记录判断依据、风险信号和后续验证条件 | 可追溯的决策日志和次日参考信息 |

整体上，这是一套从“市场判断”逐步收敛到“实际交易”的漏斗式流程。上游环节出现风险信号时，下游环节不能继续激进加仓。

### 2. 第一步：读取账户与市场基础数据

每天开始决策前，Bot101 首先读取已经准备好的账户和市场信息，包括：

- 账户总资产、可用现金及当前仓位；
- 当前持有基金、基金净值及持仓盈亏；
- 账户累计收益、单日收益和最大回撤；
- 主要宽基指数的趋势和均线位置；
- 市场估值、风险偏好、情绪、波动率和资金状态；
- 最近交易记录和历史决策经验。

这一环节的目的是让后续判断基于当前账户的真实状态，而不是只根据市场涨跌给出孤立建议。

### 3. 第二步：判断市场环境

Bot101 会从多个维度判断市场所处环境：

- **宏观环境**：经济增长、通胀、货币政策、财政政策及国内外重要事件；
- **市场趋势**：主要指数处于上涨、震荡还是下跌趋势；
- **估值位置**：市场整体处于便宜、合理还是偏贵区间；
- **风险偏好**：市场处于积极、中性还是防御状态；
- **市场情绪**：判断市场是否过热、恐慌或处于正常区间；
- **资金与波动**：分析资金流向、成交活跃度和市场波动率。

最终形成三类核心结论：

1. 当前是否适合承担较高权益风险；
2. 市场属于上涨、区间震荡还是下跌阶段；
3. 当前估值是否支持继续增加仓位。

### 4. 第三步：识别和维护市场主线

在完成市场环境判断后，Bot101 会分析当前是否存在具备持续性的行业或主题主线，例如科技、消费、红利、医药、军工或其他产业方向。

主线识别并不只看单日涨幅，而是综合考察：

- 板块相对强弱和趋势；
- 是否持续出现在市场强势方向中；
- 是否站在重要中长期趋势线上方；
- 资金、政策和基本面是否形成支持；
- 主线是否具备足够的持续时间和市场集中度。

组合通常划分为：

- **核心主线**：持续性更强、作为主要收益来源的方向；
- **辅助或卫星方向**：处于早期、弹性较高但确定性相对较低的方向；
- **现金或防御资产**：市场风险升高时用于控制组合波动。

为防止追涨杀跌，Bot101 使用连续多日确认、最小持有期和调仓冷却期等规则。单日排名变化通常不会直接触发换仓。

### 5. 第四步：先复核旧持仓，再考虑新增投资

Bot101 每天先检查已有持仓，再决定是否需要买入新的基金。主要检查内容包括：

- 原有投资逻辑是否仍然成立；
- 所属行业或主题趋势是否已经破坏；
- 持仓是否达到退出或风险控制条件；
- 当前浮盈、浮亏和持有时间是否支持继续持有；
- 是否存在明显优于现有持仓的新机会；
- 换仓带来的交易成本是否值得。

如果原有主线和持仓逻辑没有被证伪，默认选择继续持有。这样能够减少无效换手，避免系统因为每天重新分析而每天重新交易。

### 6. 第五步：筛选合适的基金载体

只有当系统确认需要新增或替换某一投资方向时，才会进入基金筛选环节。Bot101 不会每天对全部基金进行逐只扫描，而是在已经确定的板块中收敛候选范围。

基金筛选主要考虑：

- 对目标指数或行业的跟踪质量；
- 基金费率和长期持有成本；
- 基金规模、流动性及运行稳定性；
- 基金与目标板块的实际相关性；
- 是否属于账户当前可购买的基金范围。

通常最终保留 1—3 只候选基金，并优先选择跟踪清晰、成本合理、流动性较好的产品。

### 7. 第六步：确定总仓位和组合结构

Bot101 将市场风险状态、趋势、估值和主线置信度转换为组合仓位。基本原则如下：

| 市场状态 | 仓位处理思路 |
|---|---|
| 风险偏好较高、趋势向上、主线清晰 | 提高权益仓位，并集中配置核心主线 |
| 市场中性或区间震荡 | 保持中等仓位，控制集中度和追涨风险 |
| 风险偏好下降、趋势转弱 | 主动降低权益仓位，增加现金或防御配置 |
| 市场明显下跌或账户风险触发 | 将仓位压缩至低档，停止逆势加仓 |

组合结构通常包括核心仓、辅助仓和现金。即使市场判断积极，系统也会根据账户回撤和现有持仓情况保留一定调整空间。

### 8. 第七步：执行风险控制

在生成交易指令前，Bot101 会再次经过风险检查，主要包括：

- 账户回撤是否达到降仓阈值；
- 市场趋势是否已经发生实质性破坏；
- 持仓逻辑是否被新的数据证伪；
- 市场估值和情绪是否过热；
- 是否正在下跌趋势中对亏损仓位进行不合理补仓；
- 调仓幅度是否过小、交易是否过于频繁；
- 新的投资方向是否经过足够时间确认。

Bot101 明确禁止在下跌趋势中盲目补仓摊低成本。系统更倾向于等待趋势企稳或重新确认后再增加风险暴露。

### 9. 第八步：形成当日投资决策

完成全部分析后，Bot101 输出以下四类决策之一：

1. **维持不动**：市场和组合没有出现足够大的变化；
2. **买入或加仓**：趋势、主线和账户风险条件同时允许；
3. **卖出或减仓**：市场风险上升、趋势破坏或账户回撤触发；
4. **组合切换**：原主线被证伪，新主线经过连续确认。

每次决策同时说明：

- 市场环境判断；
- 主线与组合状态；
- 当前账户仓位；
- 具体交易动作；
- 支持该动作的主要依据；
- 后续需要观察的风险和触发条件。

### 10. 第九步：记录与次日验证

每日决策结束后，系统会保存：

- 当日市场环境和主线判断；
- 交易动作及执行结果；
- 当前组合结构和仓位档位；
- 各类连续确认计数；
- 可能推翻当前判断的证伪条件；
- 对未来不同时间周期的方向判断。

这些信息会成为下一交易日的决策参考，使 Bot101 能够在连续运行中保持策略一致性，并支持事后审计和复盘。

## 三、Bot101 每日投资约束体系

Bot101 的每日投资决策不是模型自由发挥，而是在预先设定的人设、投资范围、仓位、调仓和风控规则内完成。约束分为两类：

- **硬约束**：决定某项操作“能不能做”。条件不满足时，即使模型主观看好，也不能执行；
- **软约束**：决定在多个合规方案中“更倾向怎么做”。软约束可以随市场和证据变化，但不能突破硬约束。

### 1. 约束优先级

| 优先级 | 约束层级 | 主要作用 |
|---:|---|---|
| 1 | 投资目标与投资范围 | 确定 Bot101 的角色以及绝对不能交易的资产 |
| 2 | 账户安全与风险闸门 | 风险达到条件时限制或禁止继续增加风险 |
| 3 | 市场状态与主线规则 | 决定允许使用的总仓位区间和集中程度 |
| 4 | 持仓、调仓和交易纪律 | 决定是否可以换仓、加仓、减仓以及交易幅度 |
| 5 | 风格偏好与执行倾向 | 在合规范围内决定集中或分散、立即执行或等待确认 |

实际执行时，Bot101 先检查硬约束是否允许交易，再在允许范围内使用软约束选择符合其投资风格的方案。软约束不能覆盖投资范围、账户风控和交易禁令。

### 2. 人设与投资定位约束

Bot101 的人设不是对外宣传形象，而是固定投资行为的一组长期设定。

| 约束内容 | 类型 | 如何起作用 |
|---|---|---|
| 高风险、多指数权益基金配置员 | 软约束 | 主线清晰且趋势确认时，更倾向提高仓位并集中配置，而不是长期保持低仓位 |
| 主线投资者 | 软约束 | 优先寻找趋势、资金和基本面支持的行业主线，不平均配置所有行业 |
| 进攻有纪律 | 软约束 | 可以承受正常波动，但提高仓位必须有数据依据，不能把高风险理解为随意追涨 |
| 看对敢集中、看错快认错 | 软约束 | 主线成立时减少无意义分散；主线被证伪时主动缩仓，不拖延处理 |
| 不设固定年化收益目标 | 软约束 | 不为完成短期收益数字强行交易，重点是抓住趋势和避免重大错误 |
| 所有决策必须有数据依据并可复盘 | 硬约束 | 买卖必须说明市场、趋势、资金、账户或风险依据，不能只凭感觉 |

这组约束使 Bot101 比中低风险策略更愿意在强主线阶段集中持仓，也更能容忍正常回撤和盈利回吐；但进攻性必须建立在证据和纪律之上。

### 3. 投资范围硬约束

| 硬约束 | 具体规则 | 生效方式 |
|---|---|---|
| 只投资权益基金 | 只在权益基金内部进行多指数配置 | 非权益产品不会进入候选池 |
| 不交易个股 | 不直接买卖单只股票 | 行业机会必须通过指数基金或基金产品表达 |
| 不配置非权益资产 | 不买债券、货币、黄金和商品基金 | 风险升高时通过降低权益仓位、提高现金比例防守 |
| 每条主线只持有一只基金 | 同一行业或主题只选择一个基金载体 | 防止高度相关基金造成“假分散”和重复费用 |
| 只购买当日可交易基金池内产品 | 候选必须属于账户可买范围 | 不在可买池中的基金即使评分较高也不能下单 |
| 不修改系统基础设施 | Bot101 只进行投资决策 | 防止模型通过修改程序或配置绕过交易规则 |

这些规则在每日流程最前端生效。资产一旦不符合范围要求，就不会进入后续比较、仓位和下单环节。

### 4. 风险偏好与回撤约束

Bot101 的高风险偏好是愿意承担合理波动以换取收益弹性，不代表可以接受失控亏损。

| 约束内容 | 类型 | 如何起作用 |
|---|---|---|
| 可以接受约 8%—10% 的阶段性账户回撤 | 软约束 | 正常回撤不会自动触发清仓，避免为追求零回撤而错过主升行情 |
| 对盈利回吐相对宽容 | 软约束 | 已有利润且趋势未坏时使用更宽保护线，让盈利继续运行 |
| 回撤逼近强风控区时必须降风险 | 条件触发型硬约束 | 回撤逼近约 15% 或达到系统账户闸门时，优先降低总仓位和集中度 |
| 严禁失控深亏 | 硬约束 | 即使仍主观看好，也不能无视账户风险继续加仓 |
| 投资逻辑证伪时必须重评或缩仓 | 条件触发型硬约束 | 主线失效、趋势持续破坏、资金和预期同步转差时必须处理风险 |
| 正常波动不能被误判为证伪 | 软约束 | 单日下跌或普通浮亏通常不足以离场，需要区分噪声与逻辑破坏 |

风险约束按“账户风险优先于机会判断”生效。机会再强，也必须先通过账户回撤和市场趋势检查；一旦触发强风控，目标仓位会被压低。

### 5. 仓位控制约束

Bot101 的仓位由市场风险状态、趋势和主线强度共同决定，而不是由模型任意给出。

#### 5.1 市场状态与总仓位

| 市场与主线状态 | 典型总仓位 | 约束作用 |
|---|---:|---|
| 风险偏好较高、强主线、上涨趋势 | 80%—100% | 允许进攻和集中；长期低于 60% 会被视为判断与仓位不一致 |
| 风险偏好较高、中等主线 | 70%—90% | 保持较高仓位，但增加辅助仓和现金缓冲 |
| 风险偏好较高、弱主线或无明确主线 | 50%—70% | 禁止重仓单一主题，等待进一步确认 |
| 中性或震荡市场 | 30%—50% | 限制主攻仓，不主动扩大集中风险 |
| 防御或风险偏好下降 | 0%—30% | 原则上清理主攻仓并提高现金比例 |

仓位区间属于**状态触发型约束**。Bot101 可以根据估值、回撤和证据强弱选择区间上沿或下沿，但不能在防御状态下维持进攻型高仓位。

#### 5.2 单项仓位与组合结构

| 约束内容 | 类型 | 如何起作用 |
|---|---|---|
| 单只基金仓位不超过 60% | 硬约束 | 防止单一产品风险过度集中 |
| 单一主题总仓位不超过 85% | 硬约束 | 即使主线很强，也保留组合缓冲 |
| 每只基金原则上至少占 8% | 硬约束 | 不建立缺乏实际影响、只增加费用的“装饰仓” |
| 持仓数量不少于 2 只、不超过 6 只 | 硬约束 | 保持多基金属性，同时避免过度分散 |
| 典型持仓数量为 2—4 只 | 软约束 | 主线清晰时偏向 2—3 只，分歧较大时可增加到 4—5 只 |
| 采用主攻、辅助和现金三层结构 | 软约束 | 根据市场状态调整三部分比例，而不是平均分配 |
| 高相关基金不重复重仓 | 硬约束 | 防止基金数量增加但实际风险没有分散 |

### 6. 调仓习惯与换手约束

Bot101 追求收益弹性，而不是交易频率。每天运行流程不等于每天必须调仓。

| 约束内容 | 类型 | 如何起作用 |
|---|---|---|
| 先复核旧持仓，再考虑新基金 | 硬流程约束 | 原持仓仍符合市场和主线逻辑时，默认继续持有，不每天重建组合 |
| 无明确触发时默认维持不动 | 软约束 | 将继续持有作为日常基准动作，降低无效换手 |
| 单次调仓幅度原则上不低于 20% | 硬约束 | 禁止用 2%—5% 的碎片化交易反复试错；剩余容量不足时除外 |
| 新候选至少多赢两个关键维度才能替换旧持仓 | 硬约束 | 必须在主线、趋势、资金、回撤或风险收益等方面有明显优势 |
| 同主题换基金必须存在实质优势 | 硬约束 | 不能仅因短期收益略高换基，必须在费率、规模、跟踪或风险收益上更优 |
| 持有不足 7 天原则上不做往返交易 | 条件触发型硬约束 | 除非风险切换、账户闸门或主线直接证伪，否则避免短期买卖 |
| 主线切换需要多项证据确认 | 硬约束 | 至少需要趋势、资金、景气等维度中的两项确认，不能因单日波动切换 |
| 切换主线时同步完成仓位迁移 | 硬约束 | 卖出旧主线后把新主线补到目标区间下沿，避免长期现金空窗 |
| 考虑申购费、赎回费和卖飞成本 | 软约束 | 新机会的优势必须足以覆盖显性费用和机会成本才值得调仓 |

这些约束形成“低频但有力度”的调仓习惯：平时保持组合连续性，主线或风险状态真正变化时才进行有实际影响的调整。

### 7. 买入、加仓和卖出行为约束

| 交易行为 | 硬约束 | 软约束与倾向 |
|---|---|---|
| 新建仓 | 必须属于确认后的主线或允许的辅助方向，并通过基金筛选 | 高置信度时可较快建立高仓位，中等置信度时倾向分批进入 |
| 加仓 | 下跌趋势中的亏损仓位严禁补仓摊薄成本 | 只在趋势未坏、主线仍在或盈利回调时考虑加仓 |
| 减仓 | 市场转入防御、账户回撤触发或逻辑证伪时必须降风险 | 主线轻微转弱时通常先降集中度，再决定是否退出 |
| 止盈 | 没有固定单日涨幅即强制卖出的规则 | 趋势未坏时让利润运行，对已验证盈利使用较宽保护线 |
| 止损 | 不能因高风险偏好拖延处理已证伪仓位 | 普通 5%—8% 波动不自动止损，重点判断逻辑是否失效 |
| 空仓或轻仓 | 防御状态允许大幅提高现金 | 强主线阶段不能因害怕正常回撤而长期空仓 |

“严禁在下跌趋势中对亏损仓位补仓”是最重要的交易硬约束之一，用于防止高风险偏好被错误地转化为越跌越买。

### 8. 决策一致性与可审计约束

| 约束内容 | 类型 | 如何起作用 |
|---|---|---|
| 市场判断、上涨概率和实际仓位必须方向一致 | 硬约束 | 明显看多却空仓，或明显看空却维持高仓位，会被一致性检查拦截 |
| 每日流程必须按顺序执行 | 硬流程约束 | 先检查持仓和可买池，再判断风险、主线、候选和仓位，不能先下单后补理由 |
| 结论不清楚时默认不激进 | 软约束 | 市场状态或主线无法确认时，优先降低仓位和集中度 |
| 每次交易必须记录理由和证伪条件 | 硬约束 | 支持下一交易日延续判断和事后审计 |
| 决策必须使用同一套方法论 | 硬约束 | 防止不同交易日随意改变标准来解释结果 |

### 9. 约束在每日流程中的生效顺序

Bot101 每天按照以下顺序应用约束：

1. **范围检查**：剔除非权益资产、个股和不可购买基金；
2. **账户风险检查**：检查回撤、现有持仓和重大持仓消息；
3. **市场状态检查**：确定风险状态、趋势和允许的总仓位区间；
4. **主线检查**：确认主线是否清晰以及允许的集中程度；
5. **持仓连续性检查**：判断旧持仓是否有效，是否满足持有和换仓条件；
6. **交易合法性检查**：检查单基金上限、主题上限、持仓数量、最小仓位和调仓步长；
7. **交易习惯选择**：在合规方案中决定集中或分散、一次完成或分批完成；
8. **一致性检查**：确认市场判断、目标仓位和实际交易方向一致；
9. **记录与留痕**：保存交易理由、风险信号和后续证伪条件。

Bot101 的最终交易结果可以概括为：

> 最终决策 = 市场与主线判断 × 硬约束过滤 × 风险闸门 × 软约束下的风格选择

硬约束保证系统不会越界和失控，软约束则确保 Bot101 在安全边界内保持高风险主线策略应有的进攻性、集中度和持仓耐心。

### 10. 工程层面的约束注入与执行机制

前文说明的是各项约束在投资决策中的作用。本节进一步说明这些约束如何通过工程系统真正作用到 Bot101。

从工程实现看，约束不是由单一文件或单一程序完成，而是通过五层机制共同生效：

1. **Markdown 工作区注入**：把人设、方法论和交易纪律放入模型的 system prompt；
2. **每日动态 Prompt 注入**：把当日账户、市场、持仓和触发型规则放入当天 user message；
3. **Harness 编排与工具权限控制**：控制 Bot 的运行日期、执行顺序、可调用工具和运行边界；
4. **Proxy 与交易服务硬闸门**：对不合法工具参数或订单进行修改、隔离或直接拒绝；
5. **结果校验、持久化和审计**：对输出结构、订单和策略变更进行检查和留痕。

#### 10.1 工程执行强度分级

为了避免把“写在 Prompt 里的硬规则”和“代码一定会拒绝的规则”混为一谈，本文将工程执行强度分为四级：

| 工程等级 | 实现方式 | 违反后的结果 |
|---|---|---|
| L1：软提示 | Markdown 或每日 Prompt 中的风格偏好 | 模型通常会遵循，但代码不会自动阻止交易 |
| L2：强提示与流程纠偏 | 高优先级 Prompt、每日提醒、矛盾检查块 | 模型会被要求当日纠正，但如果仍违反，订单未必被服务端拒绝 |
| L3：事后校验与审计 | 输出校验、状态记录、订单数据库和日志 | 可以发现、标记和复盘违规，但通常不回滚已经受理的订单 |
| L4：代码硬闸门 | Harness、Proxy 或交易服务直接校验 | 请求被修改、隐藏、隔离或拒绝，Bot 无法靠文字解释绕过 |

因此，前文投资规则中的“硬约束”表示策略上不允许违反；只有同时落到 L4 的规则，才属于工程意义上的物理硬约束。

#### 10.2 Markdown 如何注入 Bot101

Bot101 的长期角色和投资规则存放在 `bots/bot101/` 工作区的 Markdown 文件中：

| Markdown 文件 | 主要内容 | 工程作用 |
|---|---|---|
| `IDENTITY.md` | Bot 名称、定位、能力边界 | 固定“高风险多指数权益基金配置员”的身份 |
| `SOUL.md` | 投资性格、行为准则和安全边界 | 固定进攻风格、证据要求和认错习惯 |
| `USER.md` | 风险偏好、投资目标和投资范围 | 作为仓位力度和风险容忍度的主要来源 |
| `AGENTS.md` | 每日执行顺序、工具纪律和交易铁律 | 规定 Bot 应按什么顺序分析和操作 |
| `METHODOLOGY.md` | 市场状态、仓位表、组合结构和风控规则 | 将研究结论翻译为仓位和交易动作 |
| `MEMORY.md` | 跨日保留的重要经验与状态 | 维持多日决策连续性 |
| `EQUIPPED_SKILLS.md` 与 `skills/` | 可用分析能力及操作方法 | 规定市场研判、主线和基金筛选如何执行 |

在每个 run 启动时，World Harness 调用 `buildShadowWorkspace`，把这些文件复制到该 run 专属的影子工作区：

> `world/runtime/runs/<run_id>/workspaces/bot101/`

Bot101 实际运行时读取的是影子工作区，而不是直接读取仓库模板。这样可以做到：

- 不同 run 的规则和记忆相互隔离；
- 回测运行不会直接修改原始 Bot 模板；
- `METHODOLOGY.md` 和 `USER.md` 可以在 run 内演化并被保留；
- 策略修改可以单独记录审计日志。

Research Loop 在启动 Bot 服务时接收 `--workspace <shadow_workspace>` 参数，并通过 `buildSystemPrompt` 把工作区文件拼接进 system prompt。当前拼接顺序为：

1. Research Loop 基础系统规则；
2. 真实性与验证规则；
3. 子任务相关规则；
4. `METHODOLOGY.md`、`RESEARCH.md`、`MEMORY.md`；
5. `IDENTITY.md`、`SOUL.md`、`AGENTS.md`、`USER.md`；
6. 工作区路径约定；
7. 当前世界日期。

每个工作区文件最多注入前 **12,000 个字符**。这意味着特别长的 Markdown 文件可能被截断。为避免关键算法只存在于长文件后半段，部分判断管线 Skill 还会由 Harness 完整注入每日 Prompt。

这类机制主要承载以下约束：

- 人设和高风险偏好；
- 只做权益基金、不做个股和非权益资产；
- 主线投资风格；
- 仓位区间和组合结构；
- 单基金上限、主题上限和持仓数量；
- 不接飞刀、低频调仓和持仓耐心；
- 每次交易必须给出理由和证伪条件。

这些规则进入 system prompt 后，会影响模型每一轮分析和工具调用，但多数仍属于 L1 或 L2，并非全部由交易服务自动校验。

#### 10.3 每日动态 Prompt 如何注入触发型约束

长期 Markdown 只定义稳定规则；每天变化的账户和市场信息由 `renderDailyMessage` 生成，并作为当天的 user message 发送给 Bot101。

每日 Prompt 会根据当日情况动态注入：

- 当日世界日期和 Bot ID；
- 可购买基金白名单；
- 账户总资产、现金、持仓和在途订单；
- 持仓基金净值、盈亏、持有时间和账户回撤；
- 主要指数趋势、均线、估值和市场状态；
- 市场环境、市场主线和主线轮动报告；
- 历史决策摘要与跨日经验；
- 当日需要使用的完整分析 Skill；
- Belief 概率、历史预测校准和证据要求；
- 方法论复盘、深度研究承诺或配置宪章提醒；
- 最终输出格式和必须回答的字段。

动态 Prompt 让同一套长期规则能根据当天数据触发不同动作。例如：

- 账户回撤升高时，Prompt 会把回撤状态直接摆在模型面前；
- 上一日判断看多但当前仓位过低时，会注入“belief 与仓位不一致”的纠偏块；
- 配置宪章尚未声明时，会要求 Bot 先完成声明；
- 卫星仓复评到期时，会要求先提交结构化复评；
- 当日可买池变化时，只向 Bot 展示本 run 的候选范围。

需要注意：代码中把 belief 与仓位矛盾称为“硬拦”，但当前实现方式主要是向每日 Prompt 注入一段高优先级纠偏指令，要求 Bot 当天在“修改判断”和“修改仓位”之间二选一。它属于 L2 强提示机制，不是交易接口层面的自动拒单或回滚。

#### 10.4 Harness 如何控制运行边界

World Harness 是 Bot101 的外部编排层，负责建立环境并控制每日运行。它通过以下方式使约束生效：

| Harness 机制 | 工程作用 | 执行等级 |
|---|---|---|
| 为每个 run 建立独立影子工作区 | 隔离不同回测、不同 Bot 的规则和文件 | L4 |
| 启动独立 Bot Server | 将指定模型、工作区和配置绑定到 Bot101 | L4 |
| 按交易日循环运行 | Bot 只能在 Harness 指定的世界日期进行决策 | L4 |
| 先结算、再决策、再收盘记录 | 固定账户状态更新和每日决策顺序 | L4 |
| 生成并保存 `sent.md`、`reply.json`、`status.json` | 保存输入、输出、状态、轮数和 Token | L3 |
| 设置超时、最大轮数和工具调用上限 | 防止单日无限推理或无限调用工具 | L4 |
| 注入模型配置和工具 deny 列表 | 禁止 Bot 使用 Bash、文件写入或未授权工具 | L4 |
| 预激活常用行情工具 | 让关键工具无需额外发现即可使用，提高调用稳定性；它本身不是完整工具白名单 | L2 |
| 运行结束后记录账户快照 | 固化当日资产、持仓、收益和回撤 | L3 |

Harness 并不会逐句判断 Bot 是否真正按照“先市场、后主线、再仓位”的思考顺序进行推理；该顺序主要通过 `AGENTS.md` 和 daily Prompt 约束。但 Harness 会确保交易日期、账户状态、工具范围和运行资源不能由 Bot 自行改变。

#### 10.5 Proxy 层如何强制时间、隔离和工具权限

Bot101 不直接访问底层行情和交易服务，而是经过 World 创建的代理层。

**行情代理 `simworld-proxy` 的作用：**

- 从工具参数定义中删除 `simulated_datetime`；
- 将 Harness 当前交易日强制注入每次行情请求；
- Bot 无法自行修改查询日期；
- 隐藏部分不应直接暴露给 Agent 的原始申赎工具；
- 防止回测读取未来数据或绕过加工后的量化因子。

**基金交易代理 `fund-portfolio-proxy` 的作用：**

- 从工具参数中隐藏 `run_id`，再由代理强制注入当前 run ID；
- 从买卖工具中隐藏 `trade_date`，再注入当前世界交易日；
- 对基金详情查询强制注入当日 `as_of` 截止日期；
- 防止 Bot 把订单写入其他 run，或通过修改日期获取未来净值；
- 当存在深度研究持仓承诺时，可以在代理层直接拒绝提前卖出。

这些规则属于 L4 工程硬约束。模型即使生成了错误日期或错误 run ID，也无法把该参数传到底层服务。

#### 10.6 交易服务会物理拒绝哪些订单

买卖订单最终由 `fund-portfolio-mcp` 处理。当前服务端会直接校验并拒绝以下情况：

| 服务端校验 | 违反后的处理 | 执行等级 |
|---|---|---|
| `run_id` 缺失或不合法 | 拒绝请求 | L4 |
| 买卖理由为空 | 拒绝订单，要求补充原因 | L4 |
| 买入金额不大于 0 | 拒绝订单 | L4 |
| 基金不在当前 Bot 的 curated 可买池 | 拒绝订单 | L4 |
| 基金代码不在基金基础信息表 | 拒绝订单 | L4 |
| 账户不存在 | 拒绝订单 | L4 |
| 买入金额超过可用现金 | 拒绝订单 | L4 |
| 卖出份额超过可卖份额 | 拒绝订单 | L4 |
| 相同 pending 订单重复提交 | 返回已有订单，不重复扣款 | L4 |
| 配置宪章要求声明但尚未声明 | 拒绝买单 | L4（启用宪章时） |
| 卫星仓复评逾期 | 按宪章规则限制相关买单 | L4（启用宪章时） |
| 订单受理后资金或份额冻结 | 防止重复使用同一笔现金或份额 | L4 |

服务端受理后，订单先进入 pending 状态，并按 T 日净值定价、T+1 完成确认。该结算机制使 Bot 无法直接修改现金和持仓，只能通过受控订单接口改变账户。

#### 10.7 哪些投资“硬约束”目前仍主要依赖 Prompt

下列规则虽然在投资方法论中属于硬约束，但当前交易服务没有逐项计算和拒单，主要依靠 Markdown、每日 Prompt 和事后审计执行：

| 投资规则 | 当前主要工程机制 | 是否服务端拒单 |
|---|---|---|
| 单次调仓幅度不低于 20% | `AGENTS.md` / `METHODOLOGY.md` system prompt | 否 |
| 单只基金仓位不超过 60% | 方法论与配置宪章；普通模式主要靠 Prompt | 仅启用对应宪章能力时部分强制 |
| 单主题仓位不超过 85% | 方法论 Prompt | 否 |
| 持仓数量控制在 2—6 只 | 方法论 Prompt | 否 |
| 每只基金仓位原则上不低于 8% | 方法论 Prompt | 否 |
| 同一主线只持有一只基金 | `USER.md`、`SOUL.md`、`METHODOLOGY.md` | 否 |
| 下跌趋势中不补亏损仓 | `AGENTS.md` 和方法论 Prompt | 否 |
| 持有不足 7 天不做往返交易 | 方法论 Prompt和交易历史注入 | 否，出现特殊风险时允许例外 |
| 新候选至少多赢两个维度才换仓 | 方法论 Prompt | 否 |
| 主线切换需要多项证据确认 | Skill、方法论和每日市场报告 | 否 |
| belief 与仓位方向一致 | 每日 Prompt 纠偏块、belief 校准 | 否，当前不会自动撤销订单 |

这一区分非常重要：

> 策略硬约束表示 Bot101 按设计不应违反；工程硬闸门表示系统即使面对错误模型输出，也能物理阻止执行。

对于尚未落到服务端的策略规则，系统依靠重复注入、当日数据提醒、输出要求、日志和复盘来提高遵守率。如果未来需要更强的合规保证，可以把这些规则继续下沉到交易前置校验器中。

#### 10.8 配置宪章如何把 Prompt 规则下沉为代码规则

系统提供了可选的“配置宪章”机制，用于把部分组合规则从文字约束升级为交易服务硬约束。

启用 `charterEnforcement` 后：

1. Harness 在 run 开始时为 Bot101 创建宪章要求；
2. 每日 Prompt 检查宪章状态；
3. 未声明时，Prompt 要求 Bot 调用 `portfolio_declare_charter`；
4. 声明内容包括核心基金、单基金最大比例、卫星最小比例、最低权益阈值和复评周期；
5. 声明完成前，交易服务直接拒绝买单；
6. 卫星复评逾期时，交易服务限制相关买入；
7. 所有声明和复评写入数据库，支持后续审计。

这是一种典型的“Prompt 负责让 Bot 理解规则，服务端负责保证不能绕过”的双层设计。

#### 10.9 输出校验、记忆与审计如何发挥作用

Bot101 完成当天决策后，系统通过以下方式进行事后约束：

- `reply.json` 保存完整模型回复、工具轨迹、Token 和轮数；
- `sent.md` 保存当天实际发送给 Bot 的 Prompt；
- `status.json` 保存当天成功、失败、超时和 usage；
- 订单数据库保存买卖理由、日期、状态、费用和对应 run；
- `belief_validation.json` 检查 belief YAML 是否存在、格式是否正确、概率和证据字段是否合规；
- `MEMORY.md` 和 mem0 保存跨日经验、主线状态和风险观察；
- 策略服务记录 `METHODOLOGY.md` 的每次修改及修改原因；
- 收盘流程写入账户快照、持仓快照、收益和回撤。

Belief 校验目前属于 L3：发现格式或字段问题后生成验证结果，但不会自动撤销当天已经提交的交易。订单数据库、策略修订日志和每日运行文件共同构成可追溯审计链。

#### 10.10 约束从配置到交易的完整工程链路

Bot101 每日约束的完整工程链路可以概括为：

> 仓库 Markdown 模板  
> → World 创建 run 专属影子工作区  
> → Research Loop 将 Markdown 注入 system prompt  
> → Harness 将账户、市场和触发规则注入 daily prompt  
> → 模型在工具权限范围内生成分析与交易调用  
> → Proxy 强制注入日期和 run ID，并隐藏越权参数  
> → 交易服务执行可买池、现金、份额、理由和宪章校验  
> → 合法订单进入 pending 和 T+1 结算  
> → Harness 保存回复、订单、belief、账户快照和审计日志

不同约束的工程落点可以总结如下：

| 约束类型 | 主要工程载体 |
|---|---|
| 人设、风险偏好、交易风格 | `IDENTITY.md`、`SOUL.md`、`USER.md` system prompt 注入 |
| 仓位表、组合结构、调仓纪律 | `METHODOLOGY.md`、`AGENTS.md` system prompt 注入 |
| 主线识别和基金筛选算法 | Skill 全文或方法论注入 daily prompt |
| 当日风险、持仓和账户状态 | Harness 动态 daily prompt |
| 日期、数据时点和 run 隔离 | `simworld-proxy`、`fund-portfolio-proxy` |
| 可买池、现金、份额和订单合法性 | `fund-portfolio-mcp` 服务端校验 |
| 部分组合比例和复评责任 | 可选配置宪章服务端闸门 |
| belief 格式、输出和决策留痕 | belief validator、运行文件和数据库审计 |

因此，Bot101 的约束体系并不是简单“把规则写进一个 Markdown 文件”，而是采用 Prompt 约束、Harness 编排、Proxy 隔离、交易服务拒单和事后审计的多层防线。越接近资金和订单执行的规则，越应该下沉为 L4 代码硬闸门；投资风格和需要综合判断的规则，则更适合保留在模型上下文和方法论层。

## 四、每日决策输出示例

以 2026 年 8 月 3 日为例，Bot101 的决策过程可以概括为：

- 市场风险状态被判断为防御状态；
- 经济和市场数据偏弱，主要指数位于中长期趋势线下方；
- 市场主线在当前风险环境下不足以支持提高权益仓位；
- 账户权益仓位约为 4%，已经处于低仓位区间；
- 系统未发现必须立即卖出的新增重大风险，也不允许在下跌趋势中盲目补仓；
- 最终决定为维持不动，不买入、不卖出，并继续观察防御信号和政策落地情况。

这个案例体现了 Bot101 的设计重点：每天完成全面检查，但只有在条件充分时才执行交易。

## 七、影响 Token 用量的主要因素

Bot101 每日 Token 用量并非固定，主要受到以下因素影响：

1. **每日输入信息长度**：市场报告、宏观资讯、账户历史和持仓数据越多，输入 Token 越高；
2. **模型分析轮数**：当日调用工具和继续推理的次数越多，历史上下文会被重复带入后续请求；
3. **市场复杂程度**：风险状态切换、主线轮动或账户回撤触发时，需要更多验证；
4. **交易动作复杂度**：涉及多只基金买卖、换仓和仓位计算时，输出和工具调用会增加；
5. **历史记录长度**：连续运行积累的决策记忆如果未进行压缩，会增加后续输入；
6. **异常和重复执行**：模型重试、工具异常或同一交易日重复运行会带来额外费用。

## 八、客户展示结论

Bot101 将专业投资流程拆分为一套每天可重复执行、结果可审计的标准化决策链路。系统并非仅根据涨跌预测进行交易，而是同时考虑市场环境、产业主线、产品质量、账户回撤、持仓逻辑和交易成本。

从资源消耗看，当前稳定状态下单个 Bot 每个交易日约使用 24 万 Token，参考模型成本约 0.52 元；按 22 个交易日计算，每月模型成本约 11.46 元。即使在分析复杂度较高的交易日，单日费用通常仍处于约 1 元上下。

这使 Bot101 能够以较低的模型调用成本，持续完成每日市场检查、组合风险管理和投资决策留痕。实际商业报价还应根据模型采购价格、数据服务、服务器资源、研发运维和合规审计等整体成本综合确定。

## 九、统计口径说明

- Token 数据来自 Bot101 每日 `reply.json` 中记录的累计输入用量和输出用量；
- 本文统计的是正常每日投资决策主流程，不包含市场数据生产、行情数据库、外围报告生成和人工运营成本；
- 输入 Token 为多轮模型调用的累计输入量，而不是单次请求的最大上下文；
- 费用使用参考价格估算，不是实际结算账单；
- 若供应商采用缓存优惠、包月套餐、阶梯价格或内部协议价格，实际成本可能低于或高于本文结果；
- 月度预算仅按单个 Bot 计算，多 Bot 部署时应根据不同策略的上下文长度和分析轮数分别测算。
