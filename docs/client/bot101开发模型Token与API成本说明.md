# Bot101 Agent 开发模型、Token 与 API 成本说明

## 一、文档摘要

Bot101 Agent 的开发工作使用 **GPT-5.5** 作为主要开发模型，通过公司统一采购的 API 完成需求分析、代码生成、代码修改、调试排错、测试验证和技术文档整理。

本项目开发周期约为 **1 周**，按常规工作周计算：

- 开发天数：5 个工作日；
- 每日开发时间：8 小时；
- 合计开发时间：约 40 小时；
- 主要开发模型：GPT-5.5；
- API 来源：公司采购的企业 API。

由于目前没有取得公司 API 对应项目的完整原始账单，本说明采用“同一代码仓库中典型智能编码会话的 Token 消耗速度”进行校准，并提供公司合同单价可直接代入的计算公式。

按标准开发强度估算，40 小时开发过程约产生：

- 总输入 Token：约 **5,402 万**；
- 其中缓存输入 Token：约 **2,998 万**；
- 非缓存输入 Token：约 **2,404 万**；
- 输出 Token：约 **30.7 万**；
- 输入与输出合计：约 **5,433 万 Token**。

如果暂时使用当前公开的同级高性能开发模型参考价计算，40 小时对应的模型调用费用约为：

- **144.40 美元**；
- 按 1 美元约兑换 6.76 元人民币估算，约为 **976 元人民币**。

> 以上金额是预算估算，不是公司采购 API 的实际结算金额。实际成本应以公司的协议单价、折扣、预付额度、缓存计费规则和财务账单为准。

## 二、开发模型说明

### 1. 主要开发模型

| 项目 | 内容 |
|---|---|
| 开发模型 | GPT-5.5 |
| 使用方式 | 智能编码 Agent / API 调用 |
| API 类型 | 公司统一采购 API |
| 开发周期 | 约 1 周 |
| 工作时间口径 | 5 天 × 8 小时 = 40 小时 |
| 主要用途 | 分析、编码、修改、调试、测试和文档 |

GPT-5.5 在项目开发中不是只生成一次代码，而是持续参与完整的软件工程流程。每一项开发任务通常包含多轮模型请求，模型需要重复读取项目上下文、代码文件、工具执行结果和测试反馈。

### 2. 模型参与的主要开发工作

| 开发环节 | GPT-5.5 的主要工作 |
|---|---|
| 需求分析 | 理解 Bot101 的投资目标、账户约束和每日运行要求 |
| 架构分析 | 阅读现有仓库结构、运行框架、数据库及模型配置 |
| 策略实现 | 编写市场判断、主线识别、基金筛选和仓位管理逻辑 |
| 工具集成 | 对接行情、基金、研究、账户和记忆相关工具 |
| 数据处理 | 解析账户状态、持仓、净值、订单和运行日志 |
| 调试排错 | 分析报错、修改代码并重复运行验证 |
| 测试验证 | 执行单元测试、类型检查、回测和每日模拟运行 |
| 结果复核 | 检查交易动作、风险控制和数据一致性 |
| 文档整理 | 编写方法论、配置说明、客户说明和成本统计文档 |

因此，开发阶段的 Token 消耗主要来自项目代码和工具结果被多次带入模型上下文，而不是最终输出文字本身。

## 三、开发时间口径

### 1. 标准工作周口径

本文默认“一周开发”指 5 个工作日：

> 5 个工作日 × 8 小时/日 = 40 小时

| 项目 | 数值 |
|---|---:|
| 开发天数 | 5 天 |
| 每日开发时间 | 8 小时 |
| 总开发时间 | 40 小时 |

### 2. 如果一周包含 7 个自然日

如果实际含义是连续开发 7 天，则总开发时间为：

> 7 天 × 8 小时/日 = 56 小时

56 小时场景的 Token 和费用约为 40 小时场景的 1.4 倍。本文同时在后文给出该场景的预算结果。

## 四、Token 统计和估算方法

### 1. 为什么采用估算

公司采购 API 的项目级账单、GPT-5.5 实际合同单价和目标开发周的完整 Token 明细目前未在项目仓库中保存，因此无法把本文数字表述为财务账单中的实际发生额。

为了得到更贴近真实智能编码工作的预算，本文选取同一代码仓库中一段典型 Codex 开发会话进行校准。该样本具备以下特征：

- 工作目录与 Bot101 项目相同；
- 使用相同的 Agent 式开发方式；
- 包含代码读取、命令执行、结果分析和多轮修改；
- 会话持续约 3 小时 11 分 37 秒；
- 记录了输入、缓存输入和输出 Token。

该校准会话并非 Bot101 目标开发周的 GPT-5.5 原始账单，因此只用于估算单位时间的 Token 消耗速度。

### 2. 典型开发会话样本

| 指标 | 样本数据 |
|---|---:|
| 会话时长 | 约 3.19 小时 |
| 总输入 Token | 4,313,252 |
| 缓存输入 Token | 2,393,984 |
| 非缓存输入 Token | 1,919,268 |
| 输出 Token | 24,526 |
| 输入与输出合计 | 4,337,778 |
| 输入缓存占比 | 约 55.5% |

### 3. 折算后的每小时 Token 用量

| 指标 | 每小时估算 |
|---|---:|
| 总输入 Token | 约 1,350,588 |
| 缓存输入 Token | 约 749,617 |
| 非缓存输入 Token | 约 600,971 |
| 输出 Token | 约 7,680 |
| 输入与输出合计 | 约 1,358,267 |

智能编码 Agent 的输入 Token 较高，主要原因是每轮请求都会携带系统指令、项目上下文、部分代码、工具调用记录和前序讨论内容。缓存输入可以显著降低重复上下文的计费成本。

## 六、公司采购 API 成本计算方法

### 1. 公司合同区分缓存输入时

设公司采购合同中的单价为：

- `P_input`：非缓存输入价格，单位为元/百万 Token；
- `P_cache`：缓存输入价格，单位为元/百万 Token；
- `P_output`：输出价格，单位为元/百万 Token。

标准 40 小时场景的成本公式为：

> 开发 API 成本 = 24.038844 × P_input + 29.984665 × P_cache + 0.307188 × P_output

例如，公司合同中若非缓存输入、缓存输入和输出分别为 30 元、3 元和 180 元/百万 Token，则可以直接将三个单价代入上述公式。

### 2. 公司合同不区分缓存输入时

如果公司网关将所有输入 Token 按同一价格结算，设：

- `P_all_input`：全部输入价格，单位为元/百万 Token；
- `P_output`：输出价格，单位为元/百万 Token。

则公式为：

> 开发 API 成本 = 54.023509 × P_all_input + 0.307188 × P_output

### 3. 公司使用预付套餐或年度框架协议时

如果公司采用预付 Token 包、年度保底消费或固定额度，则需要区分两种成本：

- **边际成本**：本项目增加的 Token 是否产生额外付款；
- **分摊成本**：按照本项目 Token 占公司全部 Token 的比例分摊采购金额。

分摊公式可以写为：

> 本项目分摊成本 = 公司同期 API 总费用 × 本项目计费 Token ÷ 公司同期全部计费 Token

在对外报价时，建议使用公司财务确认后的分摊成本，而不是简单使用公开零售价。

## 八、不同开发强度预算

实际 Token 用量与任务复杂度、代码库大小、调试次数和上下文缓存效率有关。建议采用区间预算而不是单一数字。

| 开发强度 | 说明 | 40 小时总 Token | 公开参考费用 | 人民币参考费用 |
|---|---|---:|---:|---:|
| 较低强度 | 需求明确、修改集中、调试较少 | 约 2,717 万 | 约 $72 | 约 ¥488 |
| 标准强度 | 多轮分析、编码、调试和测试 | 约 5,433 万 | 约 $144 | 约 ¥976 |
| 较高强度 | 大量代码阅读、反复调试和长上下文 | 约 8,150 万 | 约 $217 | 约 ¥1,464 |

对 Bot101 这类同时涉及投资策略、行情数据、基金账户、模型调用和回测验证的 Agent 项目，建议采用标准至较高强度区间进行预算。

## 九、Token 消耗的主要来源

开发阶段的 Token 主要消耗在以下方面：

1. **代码库读取**：模型需要理解现有框架、配置和模块关系；
2. **需求上下文**：投资流程、风险规则和账户约束需要持续保留；
3. **工具执行结果**：命令输出、日志、测试失败和数据库结构会返回模型；
4. **多轮调试**：每次修改后需要重新读取相关代码和验证结果；
5. **长会话上下文**：随着开发推进，前序讨论和操作记录会重复进入请求；
6. **推理与代码输出**：模型生成方案、补丁、测试和文档产生输出 Token；
7. **上下文压缩和恢复**：长任务可能需要压缩历史信息，再继续后续开发。

由于智能编码 Agent 会持续操作代码和工具，输入 Token 通常远高于输出 Token。本次估算中输出 Token 只占总 Token 的约 0.6%，但输出单价通常高于输入单价。

## 十、如何获得精确的公司采购成本

若要将本文从预算估算升级为精确成本报告，建议向公司 API 管理方取得以下数据：

1. GPT-5.5 非缓存输入的合同单价；
2. GPT-5.5 缓存输入的合同单价；
3. GPT-5.5 输出 Token 的合同单价；
4. 是否存在长上下文附加费；
5. 是否存在批量、优先级或地域附加费；
6. 是否采用预付额度、月度保底或阶梯折扣；
7. Bot101 开发期间对应 API Key、项目或用户的 usage 导出；
8. 账单 Token 是否包含失败请求、重试和工具调用产生的额外请求。

取得上述数据后，将实际 Token 和单价代入本文第六部分的公式，即可获得准确的公司采购成本。

## 十一、客户展示结论

Bot101 Agent 使用 GPT-5.5 完成约一周的智能化开发，按 5 个工作日、每天 8 小时计算，总开发时间约 40 小时。

根据同仓库典型智能编码会话校准，开发过程预计使用约 5,433 万 Token，其中大约 55.5% 的输入 Token 可以命中上下文缓存。采用当前公开同级模型价格作为参考，模型 API 费用约为 144 美元，即约 976 元人民币。

由于项目实际使用公司采购 API，企业协议通常可能包含采购折扣、预付额度或专属结算方式，因此最终成本应以公司采购合同和项目级账单为准。本文数字适合作为项目预算、客户说明和内部成本分摊参考，不应直接替代财务结算凭证。
