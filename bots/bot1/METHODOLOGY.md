# 中证红利投资框架（方法论）

这套方法论是**规则化择时**：用三个硬阈值信号决定加减仓，不再走六维度研究框架。

- 标的：**中证红利（内码 1000157392）**
- 基准：**中证全指（内码 1000157271）** —— 用于"修正相对乖离度"与"超额收益"两处
- 数据闸门：所有因子已在 simworld-data 侧按 PIT 入库；调工具时只需传当日 `date`，无需手动设 simulated_datetime（proxy 自动注入）

## 核心信号

三个独立信号，按"先满足先动手"执行，不需要共振。

### 信号 1 —— 买入：修正相对乖离度处于历史 5% 低位

- **取数**：调 `idx_corrected_deviation(securityvarietycode="1000157392", date=T, win=200)`，读字段 **修正乖离业务分位_由低至高**。
- **触发**：业务分位 **≤ 0.05**（即当前修正相对乖离度处于近 200 个交易日最低 5%）。
- **含义**：本指数 200 日乖离率相对于中证全指 200 日乖离率的比值（regll）极度偏低 —— 剔除大盘共振后，红利**自身**被显著低估。
- **动作**：从当前仓位 **加仓一档**（步长见下文"仓位档位"）。同一信号在分位回到 > 0.10 之前**不重复触发**——避免在低位区每天连续加。

### 信号 2 —— 卖出：复合拥挤度处于历史 90% 高位

- **取数**：调 `idx_congestion_pctrank(securityvarietycode="1000157392", date=T, win=200)`，读字段 **拥挤业务分位_由低至高**。
- **触发**：业务分位 **≥ 0.90**（即当前复合拥挤度处于近 200 个交易日最高 10%）。
- **含义**：成交集中度 5 日均线（cjjzdma5）历史高位，红利交易过度拥挤——典型一致繁荣顶部。
- **动作**：从当前仓位 **减仓一档**。分位回到 < 0.80 前不重复触发。

### 信号 3 —— 卖出：超额收益 ≥ 10%（相对中证全指）

- **取数**：超额收益 = (本次持仓的累计收益率) − (同期中证全指累计收益率)。
  - 调 `portfolio_get_status`（或 `get_bot_holdings`）拿当前红利持仓的**入场日 t0** 与**入场净值 nav_t0**；当日净值/收益率从同次响应里读。
  - 调 `market_index_quote(symbols=["000985"], market="cn", start_date=t0, end_date=T)`（000985 是中证全指 6 位代码；wrapper 内部会翻成 canonical）获取基准在 [t0, T] 的累计回报；不可用时回退 `market_index_quote` 单日两次相减。
- **触发**：超额收益 **≥ +10%**（持仓期内累计，含已实现）。
- **含义**：红利已显著跑赢大盘，落袋为安——避免风格切换时把超额吐回去。
- **动作**：**清空红利仓位**（一次性出，不分档）；之后回到"等买入信号"状态。

## 仓位档位

底仓 + 信号触发的"加减档"，不做心法择时。

- **仓位中枢**：50%（红利账户净资产的一半作为常态底仓）
- **档位步长**：每次买入/卖出信号触发 = **20%** 档位移动
- **上下限**：0% 与 100%（含中枢周围）
- **现金优先**：清空（信号 3）后所有头寸回到现金；买入信号触发时**优先用现金加仓**，现金不足才考虑组合切换

举例：
- 起始 50% → 触发信号 1 → 加 20% → 70%
- 70% → 又触发信号 1 → 加 20% → 90%
- 90% → 再触发信号 1 → 加到 100%（封顶）
- 100% → 触发信号 2（拥挤）→ 减 20% → 80%
- 80% → 触发信号 3（超额 10%）→ 一次清空 → 0%

## 每日执行流程

每个交易日按下面顺序走一遍，**不做研究式的市场叙事，只做信号判读 + 执行**：

1. **取因子**：并行调
   - `idx_corrected_deviation(securityvarietycode="1000157392", date=T, win=200)`
   - `idx_congestion_pctrank(securityvarietycode="1000157392", date=T, win=200)`
2. **判信号**：
   - 修正乖离业务分位 ≤ 0.05 ？ → 候选**信号 1**（买入）
   - 拥挤业务分位 ≥ 0.90 ？ → 候选**信号 2**（卖出）
3. **算超额**（仅当前有红利持仓时）：
   - 读持仓入场日 / 入场基准 / 累计收益
   - 算同期中证全指累计收益 → 算超额收益
   - 超额 ≥ 10% ？ → 候选**信号 3**（清空）
4. **去重**：检查"距上次该信号触发后业务分位是否已退出冷却带"（信号 1 退到 > 0.10，信号 2 退到 < 0.80）；未退出则该信号当日**忽略**。
5. **执行优先级**：信号 3（清空）> 信号 2（减档）> 信号 1（加档）。同日多信号时优先级高的先做完，剩下信号再判断仓位是否仍符合触发条件。
6. **记入交易日志**：每次触发与跳过都写明 `信号编号 + 当日分位/超额值 + 调档前后仓位`，便于事后回看与方法论迭代。

## 风险底线（信号体系之外）

下面三种**不需要等信号**，立刻按底线规则处理：

- **数据缺失**：`idx_corrected_deviation` 或 `idx_congestion_pctrank` 返回 `success: false` 或 `record_count == 0` 时，**保持仓位不动**——不要凭直觉/外部猜测代替信号。连续 3 个交易日数据不可用，再向 HQ 报错。
- **样本数不足**：返回字段 `样本数` < 150（窗口 200 而样本 < 75%）时，把分位结果当**参考**而非触发——只有样本 ≥ 150 才视为有效信号。
- **基准异常**：当中证全指当日 `ma200gll` 接近 0（绝对值 < 0.005）时，`修正相对乖离度` 会失真（分母接近零），当日**只看"乖离业务分位_由低至高"原始字段**（不看修正），分位 ≤ 0.05 时仍可触发信号 1。

# 仓位管理方法论

## 唯一信仰

- 红利的超额来自**机械执行三信号**：极便宜时加，极拥挤时减，吃够 10% 超额就走。
- 不做行情叙事、不做利率/风格/估值的心法判断——所有择时已浓缩在"修正相对乖离度业务分位 ≤ 5%"和"拥挤业务分位 ≥ 90%"两个数字里。
- 仓位中枢 50%，档位 20%，止盈线 10% 超额。其它一切都是噪声。

## 三档行为对照

| 信号 | 阈值 | 调档 | 冷却带 |
|------|------|------|--------|
| 1 买入：修正相对乖离度业务分位（由低至高） | ≤ 0.05 | +20% | 退至 > 0.10 才能再触发 |
| 2 卖出：拥挤业务分位（由低至高） | ≥ 0.90 | −20% | 退至 < 0.80 才能再触发 |
| 3 清空：持仓期超额收益 vs 中证全指 | ≥ +10% | 全清 | 清空后无冷却（直接回 0%） |

## 与心法的关系

旧版的"估值/利率/风格/景气/风险/证伪"六视角**已整体退役**——不再用于决策。如果你（bot）忍不住想用宏观叙事覆盖信号，请先做下面这件事再说：

- 拉出过去 N 次该信号触发的回测结果（用 `update_my_strategy` 的审计日志倒推），看用叙事覆盖的那几次是不是更好。如果**没有可重复优势**，就别动信号——叙事是回看的语言，不是择时的语言。

# 方法论迭代机制

这套规则化框架不是刻死的。跑一段时间后，若发现某条信号系统性失灵或阈值偏了，应当用 `update_my_strategy(bot_id, strategy, reason)` **完整重写**本文档（不是 diff，是整篇新版本，带上所有要保留的内容），`reason` 一句话写清为什么改——会进修订审计、下一交易日生效。但**不轻易改**：规则化方法论的命脉在稳定，频繁重写 = 给自己添噪声。

## 一、什么时候迭代（触发是"可重复的失效模式"，不是有亏就改）

- 触发的是**模式**不是**单笔盈亏**：同一信号连续多次误导（信号 1 触发后短期反向下跌、信号 2 触发后继续拥挤还涨）、阈值穿越频率异常（一年触发 0 次或 > 10 次都不正常）、出现框架没覆盖的新机制（基准指数变更、数据口径调整、新的拥挤度因子）。
- **定期 + 事件驱动**：每跑完一轮回测（或季度）做系统性体检；遇到大回撤或明显误判时事件驱动地专项复盘。
- **单次噪声不改**：单次触发后短期回撤是分位机制的正常现象（5% 分位 ≠ 不会更低），先在交易日志/记忆里复盘，不动方法论。

## 二、迭代什么 vs 不轻易动什么

- **可迭代（参数与打法层）**：分位阈值（5% / 90% / 10% 是否调到 3% / 85% / 8%）、窗口长度（200 → 250）、档位步长（20% → 25%）、仓位中枢（50% → 40%）、冷却带宽度、超额收益的计量口径（是否含已实现收益、是否年化）。
- **不轻易动（信仰与原则层）**：唯一信仰（机械执行三信号）、规则化择时、三信号架构（便宜买/拥挤卖/超额止盈）、基准为中证全指、不用宏观叙事覆盖信号。动这些要有极强且反复验证的证据，否则就是被一段行情带偏。

## 三、怎么迭代（复盘 → 提炼 → 重写）

- **决策与结果分离**：先判断"信号触发对不对"，再看"结果好不好"。好结果可能来自坏触发（运气），坏结果可能来自好触发（分位还能更极端）——只为**过程性、可重复**的错误改方法论。
- **拿证据，不拿情绪**：迭代依据是多次样本里浮现的模式（"信号 1 近 N 次有 M 次触发后 5 个交易日内继续下跌 ≥ 5%"），不是某天的难受；能落到客观记录里最好。
- **完整重写、写清 reason**：`update_my_strategy` 整篇覆盖，重写时务必带上所有要保留的内容；`reason` 讲清"改了什么、为什么、依据是什么"，进审计日志，便于日后回看这次迭代对不对。
- **小步快迭代优于大改**：一次只调一两处（如阈值从 5% 调到 7%），让后续表现验证这次改动；避免推倒重来导致归因不清。

## 四、防过拟合（迭代的纪律）

- **别拿方法论解释亏损**：改框架不是为了让上一笔亏损"显得合理"，是为了让下一类决策更对。
- **区分噪声与结构变化**：日常分位穿越是噪声（不改）；基准指数定义变更、cjjzd 因子口径调整、中证红利成分股结构性洗牌、新的 win 选项上线是结构变化（该把新机制写进框架）。
- **保留可证伪性**：每次迭代后，框架仍要能被未来数据证伪——若改到"怎么走都对"，就是过拟合历史，等于没框架。
- **迭代也会错**：新版上线后若表现更差、或当初依据被证伪，要敢于回退或再修正——审计日志就是用来看清哪次改对了、哪次改错了。
