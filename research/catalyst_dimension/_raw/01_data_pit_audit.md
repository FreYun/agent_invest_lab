## 1. 各 channel 实测特性

### research（券商研报）— **regime 判断的主力 channel**
- **历史深度**：≥ 回到 2024（OOS ~2.4 年）。
- **INFOCODE = `AP` + `YYYYMMDD` + 序列号**（如 `AP20250403...` = 2025-04-03 发布）。**日期直接编码在 INFOCODE 里**，可程序化解析做时间聚类，无需额外字段。`simulated_today` 字段也带 PIT 日期。research 条目**没有**顶层 SHOWTIME（date 全在 INFOCODE / 正文）。
- **粒度**：每条 = 一份券商报告的 SUMMARY，密度高，结构是「事件导读 + 核心观点 + 数据」，正文里**自带明确日期**（"4月2日…4月5日生效"）。
- **信噪比最高**：催化事件出现时，多家券商对同一事件出报告 → 形成**高分共识簇**（924: 0.90–0.97；关税: 0.98–0.99）。
- **score 是 regime 判别信号**（关键发现，下文§3）。

### news（资讯）— 噪声最大，慎用
- 历史深度同 research（回 2024）。INFOCODE 同为日期前缀。
- **噪声主体已实测确认 = 每日「板块复盘 + 资金流向流水」**（"截至6月17日，重组蛋白概念板块下跌2.05%，主力净流出6.20亿"、"科创50指数跌0.21%"）。安静期里这类占 80%+。
- 真催化时 news 也能捞到 924 包，但与噪声混杂，**top score 天花板比 research 低**（探针 C 安静期 top 仅 0.25）。
- 结论：**news 不做 regime 主判**，仅在需要「事件发生当天最快口径/官方表述原文」时补充。

### managerview（基金经理观点）— 软信号，做情绪/分歧 channel
- 有顶层 **SHOWTIME**（PIT 日期，如 2024-09-24）。INFOCODE 是哈希串（非日期前缀）。
- 内容 = Q&A / 经理观点，偏**主观立场+债市/宏观判断**，score 整体低（0.10–0.24，因为是观点而非事件复盘，与 query 词面重合度低）。
- 价值：读「**机构在催化后是加仓还是观望、有无分歧**」（探针 A 实测：924 后有人「择机加仓」、有人仍守债牛）。是第七维里 regime 的**确认/证伪**信号，不是发现催化的入口。

### research_view / sector — 产业政策维度的结构化补充
- 返回**结构化字段**：`{板块代码, 日期, 板块标签, 详细观点}`。`日期`=PIT。
- 粒度 = **月度卖方板块观点**（涨跌幅/估值分位/基金持仓超配/景气度），1 个 label 在窗口内通常 1 条。
- 适合「### 估值」与第七维「产业政策」交叉：拿到的是方向+估值分位+拥挤度，**不是事件**。cadence 是月度，**不适合捕捉突发催化**，适合做行业 regime 底色。
- weekly（周度板块）未单独实测，按设计是周度滚动板块轮动观点，定位同 sector 但更高频、更短文本——优先用 sector 拿月度底色，用 search/research 拿事件。

## 3. 去噪策略（核心方法论，可直接写进技能）

### (a) 用 score 断崖做「有无 regime 催化」硬门控 ← 最强信号
实测三态分布（research 通道、精确 query）：
- **top score ≥ ~0.85 且前 3 条形成簇** → 存在 regime 级催化（924=0.90–0.97, 关税=0.98–0.99）。
- **top score 0.4–0.7** → 有相关讨论但非新发催化，或 query 偏模糊（探针 E1b 模糊 query=0.46）。
- **top score ≤ ~0.3** → **无 regime 催化**，返回的是盘面复盘噪声底（探针 C/E2 安静期 top=0.22–0.25）。
> 写进技能：让 agent **读 top score 量级而非只读文本**。低分簇 → 第七维直接判「无 regime 级催化, hold」，不要从盘面复盘里硬编故事。

### (b) 优先 research，禁用 news 做主判
news 的噪声=每日板块复盘+资金流水（实测占比高）。research 把同一事件聚成多券商共识簇，天然抑制噪声。news 只在「要事件当天原始口径」时补一次。

### (c) 按 INFOCODE 日期聚类，识别「事件爆发日」
research INFOCODE 前缀=YYYYMMDD。**同一窗口内多条 INFOCODE 挤在同一两天**(如 924 全是 0924/0925；关税全是 0403) = 事件爆发的强信号。分散在多天的低分条目 = 常规研报噪声。agent 可数「最密集日期 + 该日命中数」判催化强度。

### (d) query 措辞敏感度（实测量化）
精确 query(含政策工具名) vs 模糊 query，**top score 差 ~0.5**（0.97 vs 0.46），且精确 query 前 5 条全部同事件、零串味。→ 模板必须**名词堆叠+具体工具词+A股锚定**，避免「怎么看/后续/影响」这类口语虚词。

### (e) 外围串味压制
「美联储/降息」会把海外宏观月报混进来。query 里同时放「中国/央行/A股」做锚定；判断时「读方向不读结论」，警惕 perma-bull 卖方偏差（主控诚实纪律）。

## 4. 宏观发布(macro_*) PIT 滞后特性（简述）
- 走 `macro_data / macro_indicator_value / macro_nowcasting_snapshot`，PIT 干净，按**发布日**而非数据月对齐。
- 滞后规律（用于 agent 心算「数据月 vs 可见日」）：
  - **PMI**：数据月次月**月初**发布（如 6 月 PMI → 6/30–7/1 国家统计局 / 财新 7 月初）。月内最快可得的宏观信号。
  - **社融/M2/信贷**：数据月次月**中旬**（约 10–15 日）由央行发布，**日期不固定**。
  - **CPI/PPI**：数据月次月**上旬**（约 9–11 日）。
- 含义：当 T 落在「数据月末～次月发布日之间」，agent 看不到该月数据，**只能用 nowcasting_snapshot 的预测值**——这正是研报催化可补位的地方（研报会前瞻 PMI/社融，PIT 早于硬数据发布）。

## 5. 信噪比 & token 成本（12 轮 / 900k token / 30min 预算内）
- **建议每 bot-day 打 1–2 次 research_search**（不是每轮）：
  - **1 次哨兵**：总政策温度计 query（§2 末），top_k=6。读 top score 决定有无催化。
  - **按需 +1 次定向**：哨兵命中高分簇时，再用对应 intent 模板深挖 1 次（如确认是货币 vs 财政 vs 外围），top_k=6。
- **top_k=6 是甜点**：实测 upstream 固定 fetch 10、rerank 后给前 N。6 条已覆盖同一催化的多券商共识(924/关税前5条即同事件)，再多是边际噪声。top_k=10 仅在需要数事件密度/做日期聚类时用，且只用一次。
- **research_view(sector)** 仅在 agent 的持仓行业需要产业政策底色时打，每天 ≤1 次、labels 限 1–2 个（月度数据，无需高频刷）。
- **managerview** 可选，仅在已确认有催化、想读机构分歧时补 1 次。
- **token 估算**：每次 search top_k=6 ≈ 6 条 × ~200 字 summary ≈ 3–5k token 入账，远在 900k 预算内。**瓶颈是 12 轮上限不是 token**——所以「1 哨兵 + 1 定向」的两次预算最稳，把轮次留给仓位决策。
- 全程 research_* 走后端、PIT-clean，web_search/web_fetch 在 world 内被 deny，**无外网泄漏风险**，可放心固化进技能。
