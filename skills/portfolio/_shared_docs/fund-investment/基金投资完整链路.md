# 基金投资完整链路

**版本：** v1.0  
**起草日期：** 2026-04-23  
**适用对象：** 参与基金直投的 bot  
**定位：** 公募基金直投的完整执行链路，参考投顾 V2 架构但针对基金直投场景重新设计。  
**与投顾链路的关系：** 投顾走平台组合产品，本链路走公募基金直投；两套体系并行，共享市场环境判断层，选品层完全独立。

---

## 一、与投顾链路的核心差异

投顾链路的 Phase B 是从**几十个投顾产品**里挑组合，产品本身已经做了分散。  
基金链路的 Phase B 是从**全市场几千只公募基金**里自主筛选，必须自己构建分散组合。

这带来三个根本不同：

| 维度 | 投顾链路 | 基金链路 |
|------|---------|---------|
| 选品池 | 几十个投顾产品，平台已筛过 | 全市场公募基金，需要多轮筛选漏斗 |
| 选品决策权 | bot + 研究部确认 | **bot 完全自主** |
| 个性体现 | 主要靠权重配比和风险带选择 | **从选基开始就要体现个性**——选什么基金经理、偏好什么风格、容忍多大回撤 |

## 二、整体架构

```
Phase A    市场数据刷新（research-mcp）         → 基金池 + 市场指标更新
Phase A.5  数据新鲜度闸门                       → 判断是否允许进入决策链路
Phase B-1  能力圈宣告 + 范式选择                → 闸门 + 写 fund_paradigm_runs
Phase B0   三大类资产判断 + 配置比例             → 股/债/黄金/现金目标比例（按范式调整重点）
Phase B    个性化选基（四层漏斗）                → 资产匹配 → 风格行业 → 业绩 → 个性终选（按范式分支）
Phase C    每日巡检（择时×调仓 一轮完成）        → 逐只扫描→组合汇总→资金再分配→统一出单（按范式分支）
Phase D    收益快照                             → 记录当日净值和损益
Phase E    markdown 归档                        → 从事实源反写到文件
```

## 三、Phase A：市场数据刷新

### 刷新内容

使用 research-mcp 工具获取基金数据：

| 数据 | 工具 | 频率 |
|------|------|------|
| 基金基本信息 | `fund_basicinfo` | 每周一次（基本面变化慢） |
| 基金净值 | `fund_basicinfo` / `get_fund_nav_and_return` | 每个交易日 |
| 基金业绩表现 | `get_fund_performance` | 每个交易日 |
| 基金持仓风格 | `get_fund_style_analysis` / `get_fund_industry_holding` | 每季报更新后 |
| 基金经理信息 | `get_fund_manager_info` | 每月一次 |
| 市场指数行情 | `market_overview` / `get_ashares_index_quote` | 每个交易日 |
| 恐慌指数 | `get_ashares_gvix` | 每个交易日 |

### 刷新顺序

1. 先刷市场指标（指数、恐慌指数、国债收益率）
2. 再刷持仓基金的最新净值和业绩
3. 最后刷候选池基金数据（如有选品需求）

## 四点五、Phase B-1：能力圈宣告 + 范式选择（2026-04-29 三层框架前置闸门）

> **设计理由与完整规格**见 `docs/superpowers/specs/2026-04-29-fund-investing-framework-design.md`

### 位置

```
Phase A.5 数据新鲜度闸门
─────────────────  ↓ 新增 ↓
Phase B-1 能力圈宣告 + 范式选择     ← 本节
─────────────────  ↑ 新增 ↑
Phase B0 市场环境判断
```

### 做的事

1. 读 `workspace-{bot}/memory/portfolio/fund/能力圈宣告.md` 顶部 yaml frontmatter
2. 闸门：`capability_levels` 全 false/null → 写 `paradigm_active=SKIP`，跳过 B0/B/C
3. 范式选择（per bot）：
   - 单能力圈 → 自动绑定该范式
   - 复合能力圈 → 首次走 default_paradigm；后续保持当前（切换信号由 bot 在策略摘要里自定）；切换间隔 ≥ 30 天
4. 写入 `fund_paradigm_runs(bot_id, trade_date, paradigm_active, capability_field, capability_value, switched_from, reason)`

### 范式与四种能力圈

| 范式 | 能力圈字段 | 持仓主轴 | 风控决策依据 |
|---|---|---|---|
| A | macro=true | 大类资产 | 宏观信号 → 整组合大类比例重定；不下沉到单基金 |
| B1 | industry_rotation=true | 行业 | 行业相对强弱 → 行业间权重切换 |
| B2 | industry_focus 非空 | 单一行业 | 主战行业自身周期 → 行业内加减仓 |
| C | fund_alpha=true | 单基金 | 单基金浮盈 + 动能 + regime → 个基止盈止损/SWITCH |

### 后续 Phase 的契约

- B0 / B / C 在执行前必须先查 `fund_paradigm_runs` 拿当日 paradigm
- 各 skill 内部根据 paradigm 走差异化分支（具体差异化逻辑由各 skill SKILL.md 描述，框架不预设）
- 数据库表 `fund_bot_reviews / fund_bot_actions / fund_allocation_runs` 各加 `paradigm` 字段做溯源

### 闸门后果（paradigm_active = SKIP）

- 当日 B0/B/C 不为该 bot 执行
- Phase D 仍可生成空快照（若已有持仓，继续按净值刷新）
- 写一行 SKIP 记录到 `fund_paradigm_runs`，运维可在 dashboard 看到"X bot 当日因无能力圈未参与"

### 季度重评

- 触发：`update-capability-circle.py`（每季度第 1 工作日 cron）
- 输入：本季度 `fund_bot_reviews / fund_bot_actions / fund_paradigm_runs` + bot 自己的日记 / 研究记忆
- 输出：重写各 bot 的 `能力圈宣告.md`（yaml frontmatter + 正文证据）
- 演进硬规则：
  - 新增能力（false → true）必须有具体证据
  - 收窄能力（true → false）随时允许
  - 非季度窗口禁止新增，允许收窄

## 五、Phase B0：市场环境判断 + 大类资产配置

**这是整个链路的起点：先对股、债、黄金三大类资产形成自己的判断，再定配置比例。**

### 市场环境四象限

| 状态 | 定义 | 关键信号 |
|------|------|---------|
| **牛市** | 上升趋势，量价齐升 | 指数 > MA60，恐慌指数低，北向净流入 |
| **震荡** | 区间波动，方向不明 | 指数围绕均线震荡 |
| **熊市** | 下行趋势，缩量 | 指数 < MA60，利差走阔 |
| **危机** | 极端冲击 | 周跌 > 8%，恐慌指数 > 30 |

### 三大类资产判断

bot 需要对每类资产独立形成观点：

| 资产 | 判断维度 | 数据来源 |
|------|---------|---------|
| **股票** | A股指数趋势、估值分位、恐慌指数、北向资金 | `market_overview` / `get_ashares_index_val` / `get_ashares_gvix` |
| **债券** | 国债收益率走势、信用利差、货币政策方向 | `get_cn_bond_yield` / `get_bond_yield_spread` / `get_cn_macro_data` |
| **黄金** | 金价趋势、美元指数、实际利率、避险情绪 | `commodity_data` / `us_macro_simple` |

每类资产给出一个观点：**看多 / 中性 / 看空**

### 大类资产配置比例

根据三大类资产观点 × 市场环境，确定配置比例：

| 大类 | 牛市 | 震荡 | 熊市 | 危机 |
|------|------|------|------|------|
| **股票类** | 50-65% | 30-45% | 15-25% | 5-15% |
| **债券类** | 10-20% | 25-35% | 35-45% | 35-45% |
| **黄金类** | 5-10% | 10-15% | 15-25% | 20-30% |
| **现金** | 5-10% | 10-15% | 15-25% | 15-25% |

> 这是基准区间，bot 根据自己对三类资产的观点在区间内微调。例如震荡市但黄金看多，则黄金可以推到区间上限 15%。

## 六、Phase B：个性化选基（最关键的阶段）

这是基金链路的灵魂。整个选基逻辑是**自上而下、逐步收窄**：

> 先定大类配置比例 → 按基金底层资产配置匹配 → 按风格和行业标签筛选 → 最后按业绩表现选出最终标的

**业绩是最后一关，不是第一关。** 先确保方向对（资产类别对、风格对、行业对），再在对的方向里挑表现最好的。

### 6.1 选基漏斗（四层筛选）

```
全市场基金（~10000+）
    ↓ Layer 1：硬性门槛 + 资产配置匹配
    │  规模/年限/状态等基本门槛
    │  基金底层的股/债/黄金配置比例是否匹配 Phase B0 的大类目标
候选池（~200-500）
    ↓ Layer 2：风格标签 + 行业标签筛选
    │  bot 根据人设选择要投的风格（大盘价值/成长/中小盘…）
    │  bot 根据能力圈选择行业方向（科技/新能源/消费…）
精选池（~30-80）
    ↓ Layer 3：业绩表现筛选
    │  在方向正确的候选里，按收益率/回撤/夏普/排名优中选优
匹配池（~10-20）
    ↓ Layer 4：个性化终选（bot 人设驱动最终取舍）
目标组合（5-8只）
```

### 6.2 Layer 1：硬性门槛 + 资产配置匹配

**第一步：基本门槛过滤**

使用 `simple_fund_search` + `fund_basicinfo` 批量筛选：

| 条件 | 阈值 | 工具 |
|------|------|------|
| 基金规模 | ≥ 2亿 | `fund_basicinfo` (FUNDSCALE) |
| 成立年限 | ≥ 2年 | `fund_basicinfo` (ESTABDATE) |
| 基金经理任职 | ≥ 1年 | `get_fund_manager_info` |
| 申赎状态 | 开放 | `fund_basicinfo` (SGZT/SHZT) |

**第二步：按大类资产配置匹配**

Phase B0 已经定好了股/债/黄金/现金的目标比例。这一步按大类分别筛选对应基金。

**股票类和债券类：从全市场筛选**

| 大类目标 | 对应基金类型 | 筛选方式 |
|---------|------------|---------|
| 股票类 X% | 股票型、偏股混合型、指数型 | `simple_fund_search(fund_type="股票型"/"混合型"/"指数型")` |
| 债券类 Y% | 债券型、偏债混合型、固收+ | `simple_fund_search(fund_type="债券型")` |

对于混合型基金，用 `get_fund_comprehensive_analysis` 穿透看底层资产配置：

```
get_fund_comprehensive_analysis(fund_code="xxx")
→ 返回 权益占比 / 固收占比 / 存款占比
→ 判断这只基金属于"偏股"还是"偏债"还是"均衡"
```

**黄金类：从固定白名单选择**

黄金类只投黄金ETF场外联接基金（跟踪 AU9999），不投贵金属主题基金。

全市场黄金ETF联接就固定几只，无需从全市场筛选，直接从白名单选（详见 `基金投资策略摘要.md` 黄金白名单章节）：

| 代码 | 名称 | 适合场景 |
|------|------|---------|
| 002610/002611 | 博时黄金ETF联接 A/C | 规模大，流动性好 |
| 000216/000217 | 华安黄金ETF联接 A/C | 规模大，费率低 |
| 000218 | 国泰黄金ETF联接A | 老牌产品 |
| 008701/008702 | 华夏黄金ETF联接 A/C | 注意限大额申购 |

选基逻辑：跟踪同一标的，业绩差异只在费率。长期持有选 A 类，定投选 C 类，费率相近时选规模更大的。

> **为什么不用 `fund_theme_screening`？** 实测 `sec_name="黄金"` 返回 0 条，`sec_name="贵金属"` 返回的是金银珠宝等混合基金，不是纯黄金ETF联接。`get_tracking_funds_by_index(index_code="AU9999")` 同样返回空。所以黄金类用固定白名单，不依赖筛选工具。

**穿透匹配逻辑：**
- 如果目标股票配置 50%，那就需要总权重约 50% 的基金落在"股票类"
- 一只偏股混合基金（权益占比 70%）占组合 20% → 贡献股票暴露 14%
- 所有基金穿透后加总应接近目标比例

### 6.3 Layer 2：风格标签 + 行业标签筛选

通过 Layer 1 后，候选基金的资产类别已经对了。这一层 bot 根据自己的人设，选择具体要投什么风格、什么行业。

**风格维度：**

使用 `get_fund_style_analysis` 获取每只基金的风格标签：

| 风格 | 说明 | 适合的 bot 类型 |
|------|------|---------------|
| 大盘价值 | 低估值蓝筹，波动低 | 稳健型、"慢慢变富"型 |
| 大盘成长 | 龙头成长股，中等波动 | 均衡型 |
| 中小盘成长 | 高弹性，高波动 | 进取型、"追主线"型 |
| 均衡型 | 不偏科不偏大，分散 | 中性型 |

**行业维度：**

使用 `get_fund_industry_holding` + `get_fund_sector` 获取行业暴露：

| bot 能力圈 | 行业筛选规则 |
|-----------|-------------|
| A档（深度跟踪） | 可选该行业的主题基金作为卫星仓 |
| B档（关注过） | 只通过宽基指数间接暴露，不选行业基金 |
| C档（证据不足） | 直接排除该行业的主题基金 |

**个性化在这一层体现：**

不同 bot 面对同样的候选池，会做出不同的风格和行业选择：

| bot 人设特征 | Layer 2 选择倾向 |
|-------------|----------------|
| 稳健型 | 大盘价值 + 均衡，回避中小盘 |
| 进取型 | 大盘成长 + 中小盘，可加行业主题 |
| 科技能力圈A档 | 可选科技行业基金作为卫星（具体权重由 bot 自定） |
| "慢慢变富" | 偏好均衡型基金经理，不选极致风格 |
| "追主线" | 偏好行业轮动型经理，风格可以更锐 |

> 风格分散、单风格集中度、行业主题占比上限等均由 bot 在 `基金投资策略摘要.md` 里按人设自主定义，链路文档不强制。

### 6.4 Layer 3：业绩表现筛选

经过 Layer 1（资产类别对）和 Layer 2（风格行业对）之后，候选池已经缩小到方向正确的基金。这一步在正确的方向里**优中选优**。

使用 `get_fund_performance` 逐只评估：

| 指标 | 筛选标准 | 来源 |
|------|---------|------|
| 近一年收益率 | 同类排名前 1/2 | `get_fund_performance` |
| 近两年收益率 | 同类排名前 1/2 | `get_fund_performance` |
| 近两年最大回撤 | 同类排名前 1/3 | `get_fund_performance` |
| 夏普比率（近两年） | ≥ 1.0 | `get_fund_performance` |
| 业绩稳定性 | 近四个季度中至少3个季度排名前 1/2 | `get_fund_performance` |

补充评估：

| 指标 | 工具 | 目的 |
|------|------|------|
| 基金经理历史 | `get_fund_manager_info` | 任职年限、管理规模、历史业绩 |
| 换手率 | `get_fund_turnover_rate` | 低换手 = 长期持有型（稳健型bot偏好） |
| 费率 | `fund_rate` | 同等业绩下选费率更低的 |
| 重仓股集中度 | `get_fund_top_stocks` | 前十大占比是否合理 |
| 超额收益 | `get_fund_index_return` | 相对基准的alpha稳定性 |

### 6.5 Layer 4：个性化终选（bot 人设驱动）

到这一步，剩下的 10-20 只基金在资产类别、风格行业、业绩表现上都已合格。最终选出 5-8 只组成目标组合，这是 **bot 个性的终极表达**。

个性化维度从以下文件读取：

- `IDENTITY.md` → 人设定位
- `SOUL.md` → 核心价值观、投资底色
- `投资策略摘要.md` → 风险偏好、能力圈、产品偏好

#### 终选决策规则

| 决策维度 | 如何体现个性 |
|---------|------------|
| **基金经理偏好** | "慢慢变富"型选任职3年+、低换手的经理；"追主线"型选行业轮动能力强的经理 |
| **集中度偏好** | 均衡型 bot 选持仓分散的基金；锐度型 bot 可接受集中持股 |
| **回撤容忍** | 稳健型 bot 在同等收益下选回撤更小的；进取型可接受更大回撤换更高收益 |
| **重叠度检查** | 检查候选基金之间的重仓股重叠度，排除高度雷同的品种 |
| **组合完整度** | 确保最终组合在风格、行业、基金公司上足够分散 |

#### bot1 个性化终选示例

bot1（来财妹妹）的人设驱动的终选逻辑：

```
✓ 优先选偏股混合型，而非纯股票型（中等偏稳健）
✓ 可选 1 只科技/新能源行业基金作为卫星（A档能力圈）
✓ 偏好任职 3 年+、换手率低于同类的经理（慢慢变富）
✓ 现金保留 10-15%，不满配（分批上车习惯）
✗ 不选最大回撤过大、自己拿不住的基金（具体阈值由 bot 自己在策略摘要里定）
```

> 上述只是示例，bot1 完整的人设偏好（权重上限、回撤红线、能力圈赛道）以其 `memory/portfolio/fund/基金投资策略摘要.md` 为准，链路文档不复制。

## 七、Phase C：每日巡检（择时 × 调仓 一轮完成）

> **择时逻辑直接套用投顾体系**（详见 `workspace/skills/portfolio/_shared_docs/tougu/择时决策框架.md`），仅在数据源、费率约束、结算延迟上做基金直投适配。

### 设计原则：一轮扫描、统一出单

**择时和调仓不是先后两个步骤，而是同一个巡检回合的两个视角：**

- **单基金视角（择时）**：这只基金该不该卖/加？→ 决定哪些钱会被释放
- **组合视角（调仓）**：大类配置偏差多少？→ 决定释放的钱去哪

两个视角在**"资金再分配"**这一步汇合——择时释放的现金 + 配置偏差需要补的方向 = 一份统一的操作清单。

```
T 日晚间（净值更新后）
  Step 0  确认昨日订单 + 刷新持仓      → 在途订单落地、净值/收益率更新
  Step 1  逐只扫描（择时 + 异常检测）  → 每只基金的独立动作
  Step 2  组合层面汇总                → 释放现金合计 + 配置偏差
  Step 3  资金再分配                  → 释放的现金去哪（两个视角汇合）
  Step 4  生成操作清单                → 按风险优先级排序

T+1 日
  统一下单（买卖同天提交）            → 以 T+1 日净值成交
```

### 7.1 核心原则

每只基金的加减仓决策由**两个维度**共同决定：

> **基金自身表现（赚了多少/亏了多少/从高点回撤了多少） × 市场大环境（牛/熊/震荡/危机） = 最终动作**

只看基金不看行情 → 熊市里抄底接飞刀。只看行情不看基金 → 赚了很多也不止盈。两个维度缺一不可。

### 7.2 产品维度：持仓盈亏 + 近期动能

同样累计 +2% 的基金，有的是稳步上涨（好基金），有的是先涨 +10% 又跌回来（已转弱）。所以要同时看：

- **持仓盈亏状态**：bot 自己的浮盈浮亏
- **近期动能状态**：基金本身近期的表现强弱

#### 7.2.1 持仓盈亏状态（五档）

每日巡检时，对每只持有基金计算：

```
累计收益率 = (当前净值 / 建仓净值 - 1) × 100%
区间最大回撤 = (当前净值 / 持有期最高净值 - 1) × 100%
```

| 产品状态 | 定义 | 含义 |
|---------|------|------|
| **大幅盈利** | 累计收益 ≥ 止盈阈值 | 要不要落袋？ |
| **小幅盈利** | 0% < 累计收益 < 止盈阈值 | 在赚但没到止盈线 |
| **微亏** | 止损阈值 < 累计收益 ≤ 0% | 还没到止损线 |
| **大幅亏损** | 累计收益 ≤ 止损阈值 | 要不要认错？ |
| **高点回撤** | 区间回撤 ≥ 加仓阈值，但累计仍为正 | 从高点跌了一段，总体还赚着 |

> 阈值因 bot 人设不同而不同（见 7.4），同一只基金在不同 bot 眼里可能归入不同状态。

#### 7.2.2 近期动能状态（五档）

使用 `get_fund_performance` 获取基金近期业绩（对应投顾体系的 `tougu_performance`）：

```
近一月收益率    = get_fund_performance → 近一个月收益率
近三月收益率    = get_fund_performance → 近三个月收益率
近一月最大回撤  = get_fund_performance → 近一个月最大回撤
```

| 动能状态 | 判定规则 | 含义 |
|---------|---------|------|
| **加速向上** | 近一月 ≥ +5% 且 近一月 ≥ 近三月 × 0.45 | 趋势强劲，短期跑赢中期节奏 |
| **稳步向上** | 近一月 +2%~+5% 或 近一月 > 0 且 近一月最大回撤 ≤ -3% | 温和上涨，无明显回调 |
| **停滞** | -2% ≤ 近一月 ≤ +2% | 横盘，方向不明 |
| **减速但未转** | 近一月 < 0 且 近三月 > 0 | 近期回调但中期仍在涨 |
| **已转弱** | 近一月 ≤ -3% 或 近一月最大回撤 ≤ -8% | 动能明确转弱，趋势反转信号 |

> 数据缺失时（如新买入基金没有三个月数据）：默认归入"停滞"。但如果是"应该有数据但获取失败"，则归入"数据缺失"——暂停动能修饰，只走矩阵+硬阈值（见 7.12）。

#### 7.2.3 两个维度的配合：揭示隐蔽信号

| 组合 | 含义 | 信号 |
|------|------|------|
| 盈利 + 加速向上 | 买对了且还在起飞 | 继续持有的最强信号 |
| 盈利 + 已转弱 | 买对了但趋势反转中 | **危险**——利润在缩水 |
| 微亏 + 稳步向上 | 买晚了但基金没问题 | 耐心等，动能会拉回来 |
| 微亏 + 已转弱 | 买晚了且还在跌 | 止损信号加剧 |
| 高点回撤 + 加速向上 | 短期小回调，大趋势没破 | 逢回调加仓的经典场景 |
| 高点回撤 + 已转弱 | 趋势反转的早期信号 | **绝不抄底**，偏向止盈/减仓 |

### 7.3 市场维度：四种 regime（共享 Phase B0 输出）

由 `/market-context` skill 每日输出（详见 `workspace/skills/portfolio/market-context/SKILL.md`），基金和投顾共享同一份 `市场环境判断.md`：

| 市场状态 | regime | 典型特征 |
|---------|--------|---------|
| **牛市** | bull | 指数 > MA60、成交额放大、北向净流入、波动率低 |
| **震荡** | range | 指数在均线附近来回、无趋势、成交额温和 |
| **熊市** | bear | 指数 < MA60、缩量、北向净流出、信用利差走阔 |
| **危机** | crisis | 单周暴跌 >8%、VIX >30、千股跌停 |

### 7.4 人设驱动的阈值

每个 bot 的止盈/止损/加仓阈值由 `conviction_style` 决定：

| `conviction_style` | 代表 bot | 止损阈值 | 止盈阈值 | 加仓阈值(回撤) | 动作幅度 |
|---|---|---|---|---|---|
| **保守守护型** | bot5, bot12 | **-5%** | **+8%** | **-3%** | 小(5-10%仓位) |
| **均衡配置型** | bot1, bot6, bot11 | **-8%** | **+12%** | **-5%** | 中(10-15%仓位) |
| **主动进取型** | bot2, bot4, bot7 | **-12%** | **+18%** | **-8%** | 中大(15-20%仓位) |

**动作规则：**
- **止盈是减仓不是清仓**（每次减持 1/3 或按动作幅度）
- **止损是全部清仓**——认错要果断
- **加仓每次按动作幅度加**——不梭哈

### 7.5 决策矩阵：产品状态 × 市场环境

**这张表是整个择时逻辑的核心**——同一个产品状态，在不同市场环境下做不同决策：

```
                  bull(牛市)        range(震荡)      bear(熊市)       crisis(危机)
                  ──────────       ──────────       ──────────      ──────────
大幅盈利           HOLD             TAKE PROFIT      TAKE PROFIT     TAKE PROFIT
                  趋势中,让利润跑    落袋为安          积极止盈         立刻止盈

小幅盈利           HOLD             HOLD             REDUCE          TAKE PROFIT
                  继续持有          观望              减仓锁利         保住利润

微亏              HOLD             HOLD             REDUCE          STOP LOSS
                  给时间            耐心等            减亏             认错走人

大幅亏损           HOLD / ADD       STOP LOSS        STOP LOSS       STOP LOSS
                  牛市可能反转       认错              果断清仓         立刻清仓

高点回撤(累计正)    ADD              HOLD             REDUCE          STOP LOSS
                  牛市逢回调加仓     观察是否企稳       不接飞刀         保命
```

**怎么读这张表：**
1. 先看持仓盈亏状态（行）：这只基金现在累计赚了多少/亏了多少？
2. 再看市场环境（列）：`/market-context` 输出的 regime 是什么？
3. 交叉格 = 通用建议

### 7.6 近期动能作为决策修饰符

矩阵给出"通用方向"后，叠加近期动能做一次偏移：

| 近期动能 | 对矩阵结果的修饰 | 背后逻辑 |
|---------|-----------------|---------|
| **加速向上** | 偏向 HOLD——TAKE PROFIT 改减小份额，REDUCE 改 HOLD | 趋势强时不打断趋势 |
| **稳步向上** | 按矩阵执行，不修饰 | 正常动能，按常规决策 |
| **停滞** | 按矩阵执行，但减仓/止盈时幅度减半 | 方向不明，避免过度操作 |
| **减速但未转** | 按矩阵执行，但加仓禁用 | 动能在走弱，不是加仓时机 |
| **已转弱** | 偏向卖——HOLD 改 REDUCE，REDUCE 改 TAKE PROFIT/STOP LOSS | 动能反转，别再抱幻想 |

**优先级规则：**

```
Step 1: 产品 × 市场 → 矩阵通用建议
Step 2: 叠加"近期动能修饰"
Step 3: 叠加"市场 regime 对阈值的修正"（下节）
Step 4: 叠加"bot 人设偏移"（7.8）
```

- **硬阈值优先**——累计亏损触及止损线，一律 STOP LOSS，不管矩阵和动能怎么说
- **动能反转次优先**——已转弱的基金，不允许 ADD
- **市场 regime 最后**——决定止盈止损幅度的宽严

### 7.7 市场环境对阈值的动态修正

极端市场下所有 bot 都变得更谨慎/更进取：

| regime | 止损阈值 | 止盈阈值 | 加仓 |
|--------|---------|---------|------|
| **bull** | 放宽 1/3（更晚止损，给机会） | 放宽 1/3（更晚止盈，让利润跑） | 正常 |
| **range** | 不变 | 不变 | 不变 |
| **bear** | 收紧 1/3（更早止损） | 收紧 1/3（更早止盈） | ⚠️ 暂停加仓 |
| **crisis** | 收紧 1/2（最早止损） | 立刻止盈（阈值归零） | ⛔ 禁止加仓 |

**示例**：bot2（进取型，原止损 -12%）

| regime | 止损线修正后 | 含义 |
|--------|------------|------|
| bull | -12% × 4/3 ≈ **-16%** | 多给空间 |
| range | **-12%** | 不变 |
| bear | -12% × 2/3 = **-8%** | 熊市里亏 8% 就该走了 |
| crisis | -12% × 1/2 = **-6%** | 极端环境保命第一 |

### 7.8 人设对矩阵的调制

| `conviction_style` | 偏移方向 | 表现 |
|---|---|---|
| **保守守护型** | 偏向更早行动 | 矩阵说 HOLD → 可能提前 REDUCE；矩阵说 TAKE PROFIT → 更积极止盈 |
| **均衡配置型** | 跟随矩阵 | 基本按矩阵建议执行 |
| **主动进取型** | 偏向多扛一下 | 矩阵说 REDUCE → 可能继续 HOLD；但硬阈值触发时绝不犹豫 |

> ⚠️ **硬阈值优先**：人设阈值是硬规则，只要累计亏损 ≤ 止损阈值，一律 STOP LOSS。

### 7.9 基金直投特有：T+1 延迟与费率约束

**这是基金择时与投顾择时的最大执行差异。** 决策矩阵和动能逻辑完全一致，但执行层有三个硬约束：

#### 决策与执行的 T/T+1 节奏

基金交易的真实节奏：

```
T 日晚间  净值更新 → bot 分析持仓 + 市场环境 → 生成操作清单
T+1 日    统一下单（买入和卖出同天提交，不需要等赎回到账再申购）
T+1 日    以当日净值成交
```

| 要点 | 说明 |
|------|------|
| 买卖可以同天下单 | 赎回 A 基金 + 申购 B 基金可以同一天提交，不需要资金空窗期 |
| 成交价未知 | T 日决策时看到的是 T 日净值，实际成交是 T+1 日净值（隔夜风险） |
| 决策和执行分离 | T 日只做分析和决策，T+1 日才下单执行 |

**实操规则：**
- 止损触发后**下一个交易日立即下单**，不等"更好的价格"——多拖一天就多一天隔夜风险
- 分批建仓/减仓时，每批间隔 ≥ 3 个交易日（给前一批成交确认后留出观察窗口）
- QDII 基金赎回确认较慢（T+5~T+10），涉及 QDII 的调仓计划需提前规划

#### 7 天持有底线（铁律）

| 规则 | 说明 |
|------|------|
| **持有 < 7 天赎回 = 1.5% 惩罚赎回费** | 这是监管规定，无例外 |
| 决策系统必须检查每只基金的持有天数 | 如果持有 < 7 天，即使止损触发也必须**等到第 8 天再赎回** |
| 唯一例外：crisis 模式下可以接受 1.5% 惩罚费止损 | 保命优先于省费用 |

#### 费率敏感的调仓决策

| 场景 | 费率影响 | 决策调整 |
|------|---------|---------|
| A 类基金申购费 0.12-0.15% | 频繁申赎会累积费率损耗 | 调仓幅度 < 5% 时不动作（费率 > 收益） |
| C 类基金免申购费 | 适合可能调整的卫星仓 | 卫星仓优先选 C 类减少摩擦 |
| 赎回费按持有天数阶梯 | 7-30 天 0.50-0.75%，30-365 天 0.25-0.50% | 持有 < 30 天的减仓决策需额外考虑赎回费成本 |

### 7.10 基金异常检测（基金直投特有）

投顾不用担心的事，基金直投必须自己盯：

| 异常 | 检测方式 | 应对 |
|------|---------|------|
| 基金经理变更 | `get_fund_manager_info` 对比上次 | 标记关注，观察1个月 |
| 规模骤降（>30%） | `fund_basicinfo` 对比上次 | 立即评估是否赎回 |
| 风格漂移 | `get_fund_style_analysis` 对比上次 | 评估是否偏离选基理由 |
| 净值异动 | `get_fund_abnormal_movement` | 查原因，判断是否调仓 |
| 限购/暂停赎回 | `fund_basicinfo` (SGZT/SHZT) | 如暂停赎回，标记风险 |

> 基金异常是**独立于择时矩阵的触发通道**——即使矩阵说 HOLD，基金经理变更也要进入评估流程。

### 7.11 调仓约束

| 约束 | 值 | 说明 |
|------|-----|------|
| 最小调仓间隔 | 7天 | 冷静期 |
| 单次最大换手 | 25% | |
| 最小权重变更 | 3% | 小于不动（费率 > 收益） |
| 核心基金每周期最多换 | 1只 | |
| **7天持有底线** | 绝对禁止 | 持有<7天赎回=1.5%惩罚费 |
| 买卖同天下单 | 赎回+申购同天提交 | 无需等赎回到账再申购 |
| QDII特殊处理 | 确认较慢T+5~T+10 | 涉及 QDII 的调仓需提前规划 |

### 7.12 数据质量前置检查

所有择时决策建立在数据可信的前提之上。巡检开始前必须做数据闸门检查。

#### 全局闸门

| 检查项 | 闸门条件 | 命中后的动作 |
|--------|---------|------------|
| research-mcp 不可达 | Phase A 失败 | 跳过 Phase C，本轮只记录 |
| 基金净值无推进 | 最新净值日期未更新 | 跳过（非交易日/数据延迟） |
| 已有当日快照 | 避免重复执行 | 跳过 |

#### bot 层面的二次校验

| 检查项 | 判断逻辑 | 处理 |
|--------|---------|------|
| **动能数据缺失** | `get_fund_performance` 无近一月数据 | 该基金归入"数据缺失"，只走矩阵+硬阈值，不做动能修饰 |
| **动能数据陈旧** | 业绩数据距今 ≥ 3 天 | 动能降级为"停滞"，标注"数据陈旧，保守决策" |
| **净值异常** | 今日净值与 T-1 完全相同 | 疑似占位，仅允许硬止损动作 |

**数据缺失 vs 真停滞：**

| 产品情况 | 归入 | 决策修饰 |
|---------|------|---------|
| 真新基金（买入 < 3 个月） | **真停滞** | 按矩阵执行，幅度减半 |
| 数据应有但获取失败 | **数据缺失** | 暂停动能修饰，只走矩阵+硬阈值+regime 修正 |

### 7.13 Step 0：确认昨日订单 + 刷新持仓

**每日巡检的第一步不是决策，而是先把数据对齐——确认昨天的订单、刷新所有持仓的最新状态。**

T 日净值更新后，三件事同时发生：

| 事件 | 处理 | 更新内容 |
|------|------|---------|
| **已有持仓净值更新** | 用 T 日最新净值重新计算 | 每只基金的市值、累计收益率、区间最大回撤、大类实际权重 |
| **T-1 日买入订单确认** | 以 T 日净值成交，在途订单 → 已确认持仓 | 记录建仓净值起点、成交份额、持有天数从 T 日起算 |
| **T-1 日卖出订单确认** | 以 T 日净值成交，在途订单 → 已确认赎回 | 计算实际盈亏、更新现金余额、从持仓中移除 |

**执行流程：**

```
1. 读取在途订单（当前基金持仓.md → 在途订单表）
2. 对每笔在途订单：
   a. 获取 T 日最新净值（fund_basicinfo）
   b. 买入订单：计算成交份额 = 申购金额 / T日净值，写入持仓明细，记录建仓净值
   c. 卖出订单：计算实际到账金额 = 赎回份额 × T日净值 - 赎回费，更新现金余额
   d. 订单状态：在途 → 已确认
3. 刷新所有已确认持仓的最新净值和收益率
4. 更新账户概况（总资产、持仓市值、现金、累计收益）
5. 更新大类配置实际权重
6. 写回 当前基金持仓.md
```

> **Step 0 完成后，持仓数据才是准确的**——新买入的基金有了建仓起点，昨天卖出的已从持仓移除，所有基金的收益率基于最新净值。后续 Step 1-4 的择时判断才有可靠的数据基础。

### 7.14 Step 1：逐只扫描（单基金视角）

**前置准备：**

```
1. 读取 Step 0 更新后的持仓（当前基金持仓.md）
2. 读取市场环境判断.md → 获取 regime
3. 读取 bot 的基金投资策略摘要 → 获取 conviction_style 和阈值
4. 数据质量检查（7.12）：每只基金标注"可用动能"或"数据缺失"
```

**对每只持仓基金同时完成三项检查：**

| 检查 | 内容 | 输出 |
|------|------|------|
| **择时判断** | 盈亏状态 × 动能 × regime × 人设 → 矩阵决策（7.1-7.8） | HOLD / ADD / REDUCE / TAKE_PROFIT / STOP_LOSS |
| **异常检测** | 经理变更/规模骤降/风格漂移/净值异动（7.10） | 正常 / SWITCH / WATCH |
| **约束检查** | 持有天数 < 7天？费率影响？（7.9） | 可执行 / 推迟 / 不动作 |

```
对每只基金 {
  1. 刷新最新净值（fund_basicinfo）
  2. 计算累计收益率和区间回撤 → 归入盈亏状态（五档）
  3. get_fund_performance → 归入动能状态（五档）
  4. 按 regime 修正阈值 → 检查硬阈值（硬止损一票否决）
  5. 查决策矩阵 → 叠加动能修饰 → 叠加人设偏移 → 择时动作
  6. 异常检测（经理/规模/风格/净值）→ 如有异常，标记 SWITCH
  7. 约束过滤：
     - 持有 < 7天 且非 crisis → 推迟卖出
     - 调仓幅度 < 3% → 不动作（费率 > 收益）
  → 输出：该基金的最终动作 + 预估赎回/申购金额
}
```

> 关键点：择时和异常检测是**并行的两个触发通道**。即使矩阵说 HOLD，基金经理变更也会触发 SWITCH。

### 7.15 Step 2：组合层面汇总（组合视角）

逐只扫描完成后，站在组合高度做三件事：

**① 统计释放现金**

汇总 Step 1 中所有 REDUCE / TAKE_PROFIT / STOP_LOSS / SWITCH 赎回端的预估金额。

**② 计算大类配置偏差**

假设 Step 1 的卖出动作全部执行后，各大类的实际权重 vs 目标权重偏差是多少。

```
示例：
目标: 股票40% / 债券30% / 黄金12% / 现金18%
执行后: 股票34%(-6%) / 债券30%(0%) / 黄金12%(0%) / 现金24%(+6%)
→ 股票类欠配 6%，需要从现金补
```

**③ 判断是否需要额外再平衡**

即使单只基金都没触发择时信号，如果净值变动导致大类偏差 > 5%，也要再平衡。这是组合视角独立于择时的触发通道。

### 7.16 Step 3：资金再分配（两个视角汇合）

**这是择时和调仓合流的核心步骤。** Step 1 的择时决定了"哪些钱会被释放"，Step 2 的配置偏差决定了"释放的钱去哪"。

| 资金来源 | 再分配去向 | 逻辑 |
|---------|-----------|------|
| **STOP_LOSS 清仓** | 先进现金仓，不急于再投 | 止损说明判断可能错了，冷静一下 |
| **TAKE_PROFIT 减仓** | 配置偏差最大的大类 → 该类中有 ADD 信号的基金 | 利润再平衡 |
| **REDUCE 减仓** | 同上，或进入现金仓 | 视配置偏差大小 |
| **SWITCH 替换** | 触发迷你选品，找同大类同风格替代品 | 赎回+申购同天下单，无缝替换 |
| **再平衡需要** | 从超配大类减持 → 补到欠配大类 | 配置纠偏 |

#### SWITCH 触发迷你选品

当异常检测触发 SWITCH 时，不需要重跑完整 Phase B 四层漏斗：

1. 确定被替换基金的大类和风格标签（如"股票类-大盘成长"）
2. 从上次 Phase B 的 Layer 3 候选池（~10-20只）中找同类备选
3. 候选池中有合适的 → 直接替换
4. 候选池过期（> 1个月）或没有合适的 → 触发一次完整 Phase B 选品

#### STOP_LOSS 后的冷静期

止损不同于止盈——止损意味着"这只基金的选择可能从一开始就错了"。释放的资金**不立刻再投**，而是：

1. 进入现金仓，冷静 ≥ 7 天
2. 下一轮巡检时重新评估配置偏差
3. 如果偏差仍然大，再按正常流程补配

### 7.17 Step 4：统一出单（T+1 日一次性提交）

T 日晚间完成 Step 1-3 后，生成操作清单。T+1 日统一下单，**买卖同天提交**，全部以 T+1 日净值成交。

按**风险优先级**排序（决定下单顺序，避免平台限额冲突）：

```
优先级 1: STOP_LOSS        — 止损最紧急
优先级 2: TAKE_PROFIT      — 止盈次之
优先级 3: REDUCE           — 减仓
优先级 4: SWITCH 赎回端    — 替换的卖出
优先级 5: REBALANCE 赎回端 — 再平衡的卖出
优先级 6: ADD              — 加仓现有基金
优先级 7: SWITCH 申购端    — 替换的买入
优先级 8: REBALANCE 申购端 — 再平衡的买入
```

> 买卖同天提交、同天成交。不存在"先卖等到账再买"的资金空窗期。

**出单前约束检查：**

| 约束 | 规则 |
|------|------|
| 单次最大换手 ≤ 25% | 总卖出超过组合 25%，按优先级截断 |
| 最小调仓间隔 7天 | 距上次调仓 < 7天的基金不动 |
| 核心基金每周期最多换 1只 | 多只核心同时 SWITCH，只换最紧急的 |
| 7天持有底线 | 持有 < 7天推迟（crisis 除外） |

## 十一、bot 自主决策的边界

基金链路的 bot 完全自主，但有以下硬性边界：

### bot 可以自主做的

- 选择哪只基金
- 决定各基金的权重
- 判断什么时候调仓
- 决定调仓幅度
- 替换表现不好的基金
- 根据市场环境调整大类配置

### bot 不能突破的

**持仓硬约束（只有一条）：**
- 黄金类只买白名单内的黄金ETF场外联接基金，不买贵金属主题基金（标的纯度）

**调仓 / 交易硬约束（详见 7.11）：**
- 7 天内禁止赎回（费率铁律，crisis 例外）
- 最小调仓间隔 7 天（冷静期）
- 单次最大换手 25%
- 最小权重变更 3%（小于不动，费率 > 收益）
- 核心基金每周期最多换 1 只
- 买卖同天下单（赎回 + 申购同天提交）
- QDII 特殊处理（确认 T+5~T+10）

**单基金权重、单行业暴露、最大回撤、能力圈赛道选择等均交由 bot 自主决策**，由各 bot 在 `基金投资策略摘要.md` 里按人设定义自己的偏好/边界，链路文档不再统一约束。

## 十二点五、统一 MD 格式与 MD→DB 落库（2026-04-29 引入）

### 设计原则

参考投顾链路（`tougu-daily-refresh.py` + `tougu_md_to_db.py`），基金链路也走 **MD-only bot + 系统侧落库** 模式：

- **bot 只写 MD**，不调任何 `save_*` / `apply_*` / `init_*` MCP 写工具。
- **每份 MD 必须以 YAML frontmatter 起头**，frontmatter 是结构化字段（机器读 + 落库），`---` 之后的正文是叙事（人读 + 落库到 `*_md` 字段）。
- **cron 完成 bot CLI 后**，调 `fund_md_to_db.process_bot()` 解析 frontmatter，调 admin 端 fund-portfolio-mcp 工具写库。
- **任何一份 MD 缺失/frontmatter 不合法/校验失败** → 整轮回滚，不写任何下游表。

### 5 份 MD 文件清单（写入位置：`workspace-{bot}/memory/portfolio/fund/`）

### 校验红线（fund_md_to_db 拒绝写库的条件）

- `decision` / `action_type` / `amount` / `reason` / `trigger` / fund_code 集合属于事实输入，写错会直接影响系统落库。
- `account_before` / `account_after` / `before_weight` / `after_weight` / `nav_used` / `shares` / `fee` / 收益率类字段属于参考字段；若填写，必须和同一份 MD 内其他数字自洽，但系统最终仍会重算。
- HOLD 动作至少保证 `fund_code`、`action_type=HOLD`、`amount=0`、`reason` 完整；不要为了凑字段硬编权重、份额和手续费。

| 类别 | 失败条件 |
|---|---|
| **共有** | frontmatter 缺失 / `step` 不匹配 / `trade_date` 或 `run_id` 与 cron 不一致 |
| **共有** | `paradigm_active` 与 `fund_paradigm_runs` 当日记录不一致 |
| 投资框架 | `paradigm_active` ∈ {A,B1,B2,C} 之外 / Layer1-3 字段缺失 |
| 市场环境 | `regime` 不在白名单 / `today_target` 4 大类合计 ≠ 100±1 / `timing_stance` 不在白名单 |
| 选基 | `funds` 为空 / `target_weight` 合计 ≠ 1.0±0.01 / `funds[*].asset_class` 或 `role` 不在白名单 |
| 持仓 | `account.cash`/`total_value` 缺失或非数 / `holdings` 中存在 `fund_code` 重复 |
| 巡检 | `decision` 不在白名单 / `actions[*].action_type` 不在白名单 / 当前 active 持仓数 ≠ `actions` 数（HOLD 也要写） |

### 与 fund-portfolio-mcp 的关系

- **bot 调用**：fund-portfolio-mcp **readonly** 端（默认 28071，启动时设 `FUND_MCP_READONLY=1` 屏蔽 `save_*`/`apply_*`/`init_*`/`upsert_*` 工具）。bot 只能读 fund.db 数据 + 读 paradigm。
- **cron 调用**：fund-portfolio-mcp **admin** 端（建议 28073，无 READONLY 标志）。`fund_md_to_db.process_bot()` 用 admin 端写入 5 张表。
- 端口选 28xxx 段是因为 18071/18073 容易被其他任务占用，留出 28xxx 给 fund 专用。
