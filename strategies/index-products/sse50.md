# 上证50指数投资框架（方法论）

这套方法论是**规则化风险管理 overlay**：以估值定基仓、以波动率极值做修正，决定该拿多重的仓位。不走多维研究叙事，也**不做趋势/突破择时**。

- 标的：**上证50（000016.SH）**，可买 ETF：**510050**
- **定位先说清**：本框架是**下行保护器，不是收益增强器**。它的活儿是系统性风险/估值过热时少亏、把组合夏普托住；牛市单边上行且估值偏贵时，会主动让出一部分绝对收益——这是设计取舍，不是失灵。

## 标的特性（决定玩法）

上证50 = 大盘价值蓝筹（银行/保险/白酒/工业龙头权重高），低弹性、低波动、高流动性的核心底仓料。两条由此而来的硬约束：

1. **趋势/突破/动量择时在本标的无效**——波动太温吞，趋势系统会被反复假突破打脸（whipsaw）。**不要**用均线、donchian、动量信号决定仓位。
2. **估值信号真能用**——成分股盈利稳、分母不坍塌，股债性价比（ERP）有中枢、会均值回归，是本标的唯一承重的方向信号。

## 核心信号：直接读 `sse50_erp_vix_timing`

目标仓位由一个已在 server 端按 PIT 算好的因子给出，**不需要 bot 手算**。

- **取数**：`quant_factor(date=T)`，读 **`sse50_erp_vix_timing`** 字段，返回值 ∈ [0, 1] = 建议多头仓位（1=满仓、0=空仓）。这就是当日的**目标仓位**，直接进下方"仓位管理"做调仓（T+1、步长、成本）。
- 它已经把"ERP 估值基仓 + VIX 恐慌加仓 − VIX 自满减仓"合成完毕；ERP 分位、VIX 的 252 日 z-score 等滚动统计都在服务端算，避免手算飘移。
- **定位**：风险管理 overlay、不是收益增强器，**权重 ≤ 你的主维度**。

### 这个数字怎么来的（供理解与证伪，不用自己复算）

仓位 = `clip(基仓 + 0.40×恐慌窗口 − 0.35×自满当日, 0, 1)`：

1. **基仓 = ERP 估值锚**（慢，定方向）：ERP 近3年百分位越高=股票相对债券越便宜=基仓越重。`基仓 = 0.35 + 0.60 × (近3年百分位/100)`，夹在 [0.35, 0.95]。**下限 0.35：仅凭"贵"不清仓**（价值锚清仓=现金择时，易踏空）。

   | ERP 近3年百分位 | 基仓 | | < 20 | 0.40 | | 20–40 | 0.55 | | 40–60 | 0.65 | | 60–80 | 0.80 | | > 80 | 0.90 |

2. **恐慌加仓**（快，逆向买）：50ETF VIX 252日 z>1.5（急性恐慌）→ 之后 20 个交易日 +0.40。便宜+恐慌=高确信买点，并修正 ERP 在"贵但恐慌"时的误减仓。

3. **自满减仓**（确认卖点）：VIX z<−1.5（异常自满）→ 当日 −0.35。贵+自满=高确信卖点，也是唯一能把仓位压到基仓下限以下的信号。

> 想证伪/对照时才去调 `market_index_gzxjb(symbols=["000016.SH"])` 看 ERP 分位、`macro_50etf_vix` 看 VIX——日常执行直接用 `sse50_erp_vix_timing` 即可。

## 已知盲区（公式可推，照实说）

- **基仓是慢锚**：ERP 均值回归是月度级节奏，跟不上快速风格切换或单日冲击——那是 VIX 叠加项的活儿；当估值和 VIX 同时没给信号时，遇到风格切换会有滞后，这是结构性弱点不是 bug。
- **牛市踏空**：估值偏贵（基仓低）时遇到单边上涨，会跑输死拿——本框架以压回撤为先，接受这部分让利。
- **VIX 只覆盖系统性情绪**：它对个股/行业层面的结构性风险不敏感。

# 仓位管理方法论

## 唯一信仰

- 上证50 的活法 = **估值定基仓 + VIX 极值修正 + 死守"不靠趋势择时"**。贵则少配、便宜则多配，恐慌敢补、自满敢减，回撤来时优先保命。
- 所有择时已浓缩在"ERP 近3年百分位"和"50ETF VIX 252日 z-score"两个数字里。**不做行情叙事，不用均线/动量覆盖信号。**

## 调仓纪律

- **T+1**：信号按当日收盘计算，下一交易日执行，不偷看当日收盘后立即成交。
- **步长**：目标仓位与当前仓位差 < 5% 时不动（避免摩擦）；一次调仓幅度建议 ≤ 20%，急性恐慌加仓/自满减仓可一次到位。
- **回撤总开关**：账户级净值从峰值明显回撤时降仓、暂停加仓，优先级高于上面任何信号——防止一错再错。
- **成本**：510050 申赎费 + 7 日内早赎惩罚，避免同标的 7 日内 round-trip；本就是底仓，不该高频折腾。

## 风险底线（信号体系之外，不等信号立即处理）

降级链，逐级回退：

1. **首选**：`quant_factor` 的 `sse50_erp_vix_timing` 有值 → 用它当目标仓位。
2. **因子缺失**：`quant_factor` 不可用或该字段缺失 → 降级到 `market_index_gzxjb(symbols=["000016.SH"])` 读 ERP 近3年百分位，**只用基仓**（`0.35 + 0.60×分位/100`，关闭 VIX 加减项）。
3. **连 ERP 也缺**：`market_index_gzxjb` 返回 `success: false` 或无记录 → **保持仓位不动**，沿用上一交易日目标仓位；连续 3 个交易日不可用再向 HQ 报错。
4. **不外猜**：不要用 `research_search` 等外部源猜测因子/分位/VIX 读数；取不到就按上面降级，不臆造。

# 方法论迭代机制

规则不刻死，但**命脉在稳定，不轻易改**。

- **可迭代（参数层）**：基仓映射的分位档与上下限（0.35/0.95）、VIX z 阈值（±1.5）、恐慌窗口长度（20日）、加减仓幅度（+0.40/−0.35）、步长。
- **不轻易动（原则层）**：估值定基仓、不做趋势择时、VIX 极值逆向修正、下行保护优先的定位。动这些要有反复验证的证据，否则就是被一段行情带偏。
- **触发是模式不是单笔**：同一信号连续多次误导、阈值穿越频率异常（一年触发 0 次或过频）、数据口径变更才迭代；单次触发后短期回撤是分位机制的正常现象，不改。
- 迭代用 `update_my_strategy(bot_id, strategy, reason)` 整篇重写并写清 reason，进审计、下一交易日生效。

---

数据缺失或工具失败时按"风险底线"处理；Doris 后端超时就当没有该数据、降级或跳过，**绝不写 retry 循环反复捶**。
